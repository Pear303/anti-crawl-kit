# 14 · 开源生态与选型

> 调研时间：2026-11。只收录**仍在维护、许可证清晰、社区有规模**的项目。
>
> 判断标准不是 star 多，而是：**它能不能解决本包解决不了的问题**。
> star 数只作活跃度参考，不作质量背书。

---

## 0. 一页纸选型

| 你的问题 | 首选 | 备选 | 不要用 |
|---|---|---|---|
| Playwright 被识别 | **patchright**（本包已用） | camoufox（Firefox 引擎） | 裸 Playwright |
| Chromium 被针对，想换引擎 | **camoufox** | BotBrowser / fingerprint-chromium | 改 UA 硬扛 |
| 不想用 WebDriver | **pydoll** | nodriver / zendriver | undetected-chromedriver（停更） |
| 怀疑 CDP 泄漏 | **rebrowser-patches** 的思路 | patchright 已内置大部分 | 手工改 `Runtime.enable` |
| HTTP 接口 TLS 指纹被识别 | **curl_cffi**（本包已用） | httpcloak（Go） | 裸 requests |
| 大规模结构化抓取 | **Scrapy** | Crawlee（Node） | 自己写调度 |
| 需要浏览器 + 队列 + 重试 | **Crawlee** | botasaurus | 手写 asyncio 队列 |
| 想自检「我会不会被识别」 | sannysoft / rebrowser / creepjs | bot-signal | 凭感觉调参 |
| 想动态调试 JS 找接口 | **js-reverse-mcp** | Chrome DevTools | 只读压缩代码 |
| 遇到 Cloudflare 挑战 | **硬停 + 人工**（本包策略） | FlareSolverr（了解即可） | 自动破解 |

## 1. 反检测浏览器引擎

### 1.1 patchright（本包默认）

| 项 | 值 |
|---|---|
| 仓库 | `Kaliiiiiiiiii-Vinyzu/patchright` |
| star | 5,078 |
| 许可证 | Apache-2.0 |
| 最近更新 | 2026-11-02 |
| 语言 | TypeScript / Python |

**定位：** Playwright 的 undetected 分支。修复 `navigator.webdriver`、CDP 泄漏、命令行参数泄漏、`Runtime.enable` 痕迹。

**优点：**

- API 和 Playwright 完全一致，迁移成本几乎为零；
- 驱动**系统 Chrome**，指纹最接近真实用户；
- 本包所有示例都基于它。

**缺点：**

- 必须与 Chrome 大版本同步；
- 只解决「Chromium 自动化痕迹」，不解决 IP/行为/账号历史。

**什么时候换掉它：** 当目标站点专门针对 Chromium 自动化（不是通用风控），或者你需要 Firefox 的指纹分布。

---

### 1.2 camoufox

| 项 | 值 |
|---|---|
| 仓库 | `daijro/camoufox` |
| star | 13,039 |
| 许可证 | MPL-2.0 |
| 最近更新 | 2026-11-03 |
| 语言 | Python |

**定位：** 基于 Firefox 的反检测浏览器。在 C++ 层修改指纹（不是 JS 注入），Playwright 兼容。

**为什么值得关注：**

- **指纹分布和 Chromium 不同**。当平台对 Chromium 自动化特征做了针对性检测时，换引擎比继续调 JS 更有效；
- 指纹在引擎层生成，`navigator`、WebGL、字体、时区更自洽；
- 有 Playwright 接口，学习成本低。

**代价：**

- 需要下载独立浏览器（约 200MB），不是「系统 Chrome」；
- Firefox 的 TLS/HTTP2 指纹和 Chrome 不同，某些只适配 Chrome 的站点可能异常；
- MPL-2.0，商用需保留许可证声明。

**建议：** 作为**第二引擎**。默认 patchright，连续被针对时切 camoufox 做 A/B。

---

### 1.3 其他指纹浏览器

| 项目 | star | 说明 | 建议 |
|---|---|---|---|
| `botswin/BotBrowser` | 2.7k | Chromium 内核，统一指纹防御 | 了解；闭源成分多 |
| `adryfish/fingerprint-chromium` | 3.2k | Ungoogled Chromium 指纹版 | 适合做「干净基线」 |
| `donutbrowser/donutbrowser` | 4.2k | Rust，反检测浏览器 + profile 管理 | 多账号场景可参考 |
| `Virtual-Browser/VirtualBrowser` | 3.3k | 指纹浏览器，多账号 | 产品化方向，不是库 |

这些更适合「做产品」，不适合「写采集脚本」。本包不引入。

## 2. 无 WebDriver / CDP 直连

### 2.1 pydoll

| 项 | 值 |
|---|---|
| 仓库 | `autoscrape-labs/pydoll` |
| star | 7,133 |
| 许可证 | MIT |
| 最近更新 | 2026-10-09 |
| 语言 | Python |

**定位：** 不用 WebDriver，直接通过 CDP 控制 Chromium，提供更真实的交互。

**优点：**

- 没有 chromedriver 进程，少一个检测面；
- 原生 async；
- MIT，商用友好。

**缺点：**

- 生态比 Playwright 小；
- 页面等待、选择器等 API 和 Playwright 不同，迁移有成本；
- 同样需要处理 CDP 泄漏。

**建议：** 作为「patchright 失效时的第三条路」。不要同时维护两套。

---

### 2.2 nodriver / zendriver

| 项目 | star | 许可证 | 状态 |
|---|---|---|---|
| `ultrafunkamsterdam/nodriver` | 4,910 | **AGPL-3.0** | 2026-10 活跃 |
| `cdpdriver/zendriver` | 1,468 | **AGPL-3.0** | 2026-10 活跃 |

**定位：** undetected-chromedriver 的后继，CDP 直连。

**注意：AGPL-3.0。** 如果你的采集器要分发或提供网络服务，AGPL 的传染性需要法务确认。内部使用通常没问题。

**建议：** 了解即可。除非你已经在用 nodriver 生态，否则优先 pydoll（MIT）。

---

### 2.3 undetected-chromedriver（不推荐新项目）

| 项 | 值 |
|---|---|
| star | 12.9k |
| 最近更新 | 2025-07（停更） |

**为什么还这么多人用：** 历史积累，教程多。

**为什么不建议：**

- 依赖 chromedriver，本身就是一个检测面；
- 停更超过一年，新版 Chrome 兼容性靠社区 PR；
- 作者本人已转向 nodriver。

新项目直接用 patchright 或 pydoll。

## 3. CDP 泄漏补丁

### rebrowser-patches

| 项 | 值 |
|---|---|
| 仓库 | `rebrowser/rebrowser-patches` |
| star | 1,455 |
| 许可证 | MIT |
| 最近更新 | 2026-11-02 |
| 语言 | JavaScript |

**定位：** 给 Puppeteer / Playwright 打补丁，修 `Runtime.enable` 泄漏、`console.debug` 检测等，减少 Cloudflare / DataDome 挑战页。

**为什么值得读：**

- 它把「哪些 CDP 行为会被检测」讲得很清楚；
- patchright 已经内置了大部分修复，但 rebrowser 的**检测清单**可以作为自检表；
- 如果你用原生 Playwright，这是最低成本的补丁方案。

**怎么用：**

```bash
npx rebrowser-patches patch
```

**注意：** 它是「补丁工具」，不是「新框架」。patchright 用户不需要重复打补丁，但可以对照它的检测项检查自己的环境。

| star | 6,813 |
| 许可证 | MIT |
| 最近更新 | 2026-10-27 |
| 语言 | Python |

**定位：** 基于 curl-impersonate，伪装 TLS/JA3/JA4/HTTP2/HTTP3 指纹。

**本包用法：**


## 5. 爬虫框架

### 5.1 Scrapy

| 项 | 值 |
|---|---|
| star | 65,216 |
| 许可证 | BSD-3-Clause |
| 最近更新 | 2026-11-04 |

**定位：** Python 老牌爬虫框架。调度、去重、中间件、pipeline、限速都很成熟。

**适合：**

- 大规模、结构化、以 HTTP 为主的抓取；
- 需要分布式（Scrapy-Redis）；
- 团队协作，需要统一规范。

**不适合：**

- 需要登录、验证码、复杂 JS 渲染；
- 小规模、一次性任务（框架成本 > 收益）。

**和本包的关系：** 本包解决「浏览器 + 反风控」，Scrapy 解决「规模 + 调度」。上量后可以组合：Scrapy 做调度，本包做单页渲染。

---

### 5.2 Crawlee

| 项 | 值 |

| star | 26,331 |

| 语言 | TypeScript |

**定位：** Node 的爬虫库，内置 Playwright/Puppeteer/Cheerio，带队列、重试、指纹、代理轮换。

### 5.4 Scrapling（2026-11 新增）

| 项 | 值 |
|---|---|
| 仓库 | `D4Vinci/Scrapling` |
| star | **96,859** |
| 许可证 | BSD-3-Clause |
| 最近更新 | 2026-11-04 |
| 语言 | Python |

**定位：** 一体化 Python 爬虫框架：HTTP + stealth 浏览器 + 解析 + 并发爬虫。

**为什么值得关注：**

1. **自适应元素跟踪（adaptive element tracking）**：选择器改版后，能按元素结构/相似度重新定位，不靠硬编码 class。
2. **内置 Cloudflare Turnstile / Interstitial 处理**。
3. **MCP server + Agent Skill**：直接给 AI agent 用。
4. **Spider 架构**：并发、代理轮换、AutoThrottle、暂停/恢复、JSON/JSONL/CSV/XML 导出。

**和本包的关系：**

- 它的「自适应选择器」正好补本包 `fallback_selectors` 的不足；
- 如果不想自己维护浏览器层，可以用它的 `StealthyFetcher`；
- 但它是「框架」，接入会带来依赖和抽象层，默认不替换本包。

**判断：** 关注「自适应选择器」的实现思路；框架本身按需引入。

> **已提取实现：** [`src/anti_crawl_kit/adaptive_selector.py`](../src/anti_crawl_kit/adaptive_selector.py)
> —— 零依赖重写（tag / text / attributes / path / parent / siblings + `SequenceMatcher`），
> 示例见 [`examples/14_adaptive_selector.py`](../examples/14_adaptive_selector.py)。
> 算法思路来自 Scrapling（BSD-3-Clause），未复制其代码。

### 5.5 omk-crawling（2026-11 新增）

| 项 | 值 |
|---|---|
| 仓库 | `dmae97/omk-crawling` |
| star | 10 |
| 许可证 | Apache-2.0 |
| 最近更新 | 2026-11-05 |

**定位：** 「证据驱动升级」的爬虫路由器。

**八阶段升级链：**

```text
insane_search → curl_cffi → crawl4ai → scrapling
  → camoufox → patchright → nodriver → browser-use
```

**为什么值得学（不是用）：**

1. **升级由证据触发**：检测到空壳/TLS 阻断/WAF 页面/传输错误才升级，不是固定顺序。
2. **统一 `CrawlResult`**：记录 tool / status / timing / detection / route / stop_reason。
3. **不把拒绝伪装成成功**：失败有明确 `stop_reason`。
4. **代理池自愈**：harvest → validate → rank → rotate → score/backoff/burn/refill。
5. **Skill 形态**：`SKILL.md` + `install.sh`，给 agent 直接用。

**判断：** star 少，但方法论比很多大项目扎实。借鉴「证据驱动 + stop_reason」，不引入依赖。

### 5.6 CF-Bypass-Research（2026-11 新增）

| 项 | 值 |
|---|---|
| 仓库 | `lza6/CF-Bypass-Research` |
| star | 62 |
| 许可证 | MIT |
| 最近更新 | 2026-11-05 |

**定位：** Cloudflare 挑战的实证研究 + 生产级求解服务。

**多后端回落链：**

```text
纯协议 cfsolve（Rust，JS VM + 环境快照回放）
  → pydoll
  → Camoufox
  → FlareSolverr
```

**值得学的工程点：**

1. **纯协议优先**：不是所有挑战都要开浏览器；有 72MB 的纯协议模式。
2. **按域缓存 + prewarm**：把 18~43s 的求解挪出请求路径，热路径 5589 QPS / p99 2.93ms。
3. **看门狗**：进程活着但调用不返回（`wedged`）→ 退出码 75，supervisor 拉起干净进程。
4. **证据驱动**：`route=auto` 先探测有没有盾，没盾直接放行，0 次求解。

**注意：** 它做的是「过盾」（自动解挑战），和本包「验证墙硬停」的策略相反。只借鉴工程结构，不引入求解逻辑。

**判断：** 作为「如果一定要处理 CF」的参考，不作为默认方案。

**结论：**

- 本包默认栈（patchright + curl_cffi）都是宽松许可证；
- 引入 camoufox 要注意 MPL；
- 引入 nodriver / zendriver 前先问法务。

## 10. 本包的选型结论

### 保持默认

```text
浏览器：patchright + 系统 Chrome
HTTP：  curl_cffi（同步 / 异步都用同一套 TLS 指纹）
策略：  验证墙硬停 + 人工
```

理由：许可证干净、指纹真实、维护活跃、和现有代码零迁移成本。

### 建议新增（按优先级）

| 优先级 | 项目 | 用途 | 集成方式 |
|---|---|---|---|
| P1 | **camoufox** | Chromium 被针对时的第二引擎 | 新增 `BrowserSession(engine="camoufox")` |
| P2 | **rebrowser-patches** 的检测清单 | 自检 CDP 泄漏 | 补进 `docs/02` 和 `detector_check.py` |
| P2 | **js-reverse-mcp** | 混淆 JS 的动态调试 | 作为外部工具，写进 `docs/09` |
| P3 | **pydoll** | 无 WebDriver 的第三条路 | 只在 patchright 失效时评估 |
| P3 | **Scrapy / Crawlee** | 上规模后的调度层 | 不替换本包，做组合 |
| P2 | **Scrapling** 的自适应选择器 | 抗改版 | 参考实现，不引入框架 |
| P3 | **omk-crawling** 的 `stop_reason` | 失败可观测 | 借鉴结构，不引入依赖 |

### 不引入

| 项目 | 原因 |
|---|---|
| undetected-chromedriver | 停更 |
| botasaurus | 与 `BrowserSession` 定位重叠 |
| FlareSolverr / trawl | 自动过挑战，违背「硬停」策略，且不稳定 |
| 指纹浏览器（donut/VirtualBrowser） | 产品化方向，不是库 |
| nodriver / zendriver | AGPL，许可证风险 |
| **httpx / aiohttp** | 无 TLS 指纹伪装，是「原始版本」；异步并发用 `curl_cffi.AsyncSession`，不引入第二套 HTTP 栈。仅当目标站明确不校验指纹且必须 HTTP/2 时，才作为 optional 加回 |

## 11. 怎么验证一个新工具值不值得引入

```text
[ ] 许可证能接受吗？（AGPL 要先问法务）
[ ] 最近 6 个月有提交吗？
[ ] 它解决的是「本包解决不了的问题」吗？
[ ] 迁移成本：API 差异多大？要改多少文件？
[ ] 能不能和现有栈共存？（不要为了一个工具重写全部）
[ ] 有真实的 detector 自检数据吗？（不要只看 README）
```

**最后一条最重要：** 所有「能过 Cloudflare」的声明都要用 `tools/detector_check.py` 实测，而不是信 README。
