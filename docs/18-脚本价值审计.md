## 2. 有用，但需要配置/示例（4 个）

| 模块 | 状态 | 问题 |
|---|---|---|
| `headers.py` | 有用 | 平台 Referer 映射，CDN 防盗链需要 |
| `user_agent.py` | **已修** | 原来硬编码 Chrome 128，与 `http.py`(120)、`js_bundle.py`(131) 三处不一致 |
| `timeouts.py` | 有用 | 被 `waiting.py` / `login.py` 使用 |
| `platform_spec.py` | 有用 | 登录态三态 + 身份比对，但**没有示例**，agent 不知道怎么用 |

### 已修：UA 三处不一致

**问题：**

```text
user_agent.py   Chrome 128
http.py         Chrome 120   ← impersonate=chrome120
js_bundle.py    Chrome 131   ← impersonate=chrome120
```

TLS 指纹是 Chrome 120，UA 却是 131/128，属于自相矛盾。

**修复：**

```python
# user_agent.py
def get_ua_for_impersonate(impersonate="chrome120") -> str:
    ...

# http.py
DEFAULT_UA = get_ua_for_impersonate("chrome120")

# js_bundle.py
DEFAULT_UA = get_ua_for_impersonate("chrome120")
```

**验证：**

```bash
python -c "
from anti_crawl_kit.http import DEFAULT_UA
from anti_crawl_kit.js_bundle import DEFAULT_UA as JS
print(DEFAULT_UA == JS)  # True
"
```

## 3. 有条件有用（3 个）

### 3.1 `resources.py` — 负收益，默认关闭

模块自己的 docstring 就写了：

> 实测对加载速度提升有限；会破坏验证码图片、登录二维码。

**现状：**

- `BrowserSession(block_resources=False)` 默认关闭；
- 3 个示例都显式传 `False`；
- 实际上从没被启用过。

**判断：** 保留，但**不要在文档里推荐**。它属于「看起来优化、实际容易出事」的模块。

**建议：** 如果以后要清理，第一个删它。

### 3.2 `api_discovery.py` — 浏览器内发现

**和 `js_bundle.py` 的区别：**

| | `api_discovery` | `js_bundle` |
|---|---|---|
| 前提 | 浏览器已打开 | 零浏览器 |
| 看什么 | 页面实际发了哪些请求 | JS 包里写了哪些接口 |
| 适合 | 页面已经能正常加载 | HTML 空壳 |

**判断：** 有用，但边界没在 README 写清，容易被误用。

**建议：** 在 `docs/01` 的决策树里明确：「浏览器已开 → `api_discovery`；HTML 空壳 → `js_bundle`」。

### 3.3 `detector_check.py` — 已从「截图」升级为「判定」

**原问题：**

- 只截图 + 打印 `webdriver/plugins/languages`；
- 文档说「判断标准」，代码不做判断；
- Agent 拿到 PNG 无法消费。

**修复：**

- 输出 JSON；
- 5 项判定：`webdriver_false` / `ua_present` / `ua_not_headless` / `plugins_nonzero` / `chrome_object`；
- 新增 `ua_not_headless`：headless 模式 UA 带 `HeadlessChrome`，本身就是检测信号。

**实测：**

```text
headless  → ok=false，ua_not_headless=false，UA=HeadlessChrome/156
有头      → ok=true，ua_not_headless=true
```

**这个发现本身很有价值：** 即使 patchright 把 `webdriver` 修成 false，headless 的 UA 仍然会暴露。

## 4. 冗余 API（6 个）

这些函数/方法被导出，但**没有任何示例、工具或测试调用**：

| API | 位置 | 重复对象 |
|---|---|---|
| `challenge_now` | `challenge.py` | `ChallengeGate.check()` |
| `load_until_stable` | `loadmore.py` | `LoadMoreDriver` |
| `wait_for_login_status` | `login.py` | `waiting.py` 内部实现 |
| `human_click` | `behavior.py` | 无调用方 |
| `human_type` | `behavior.py` | 无调用方 |
| `human_click_locator` | `behavior.py` | 无调用方 |

**判断：** 不是 bug，是「API 面积过大」。

**处理建议：**

- **不删除**（避免破坏兼容）；
- 从 `__init__.py` 的 `__all__` 里移除，改为「显式从子模块导入才能用」；
- 或者保留导出，但文档不宣传。

**当前选择：** 保留导出，文档标注「高级/备选」。

**为什么不删：**

- `challenge_now` 在「只检测不抛异常」的场景有用；
- `load_until_stable` 是一行式封装，适合脚本；
- `wait_for_login_status` 是通用框架，平台适配层可能用；
- `human_*` 在需要精细控制的场景有用。

## 5. 文档承诺 vs 示例覆盖

这是本次审计最值得注意的问题：**文档推荐了，但示例没演示。**

| 文档承诺 | 示例覆盖 | 后果 |
|---|---|---|
| `behavior.py` 人类行为模拟 | 只有 `generic.py` 内部用 `human_scroll` | Agent 不知道怎么单独用 |
| `strategy.py` 多策略降级 | **无示例** | 文档推荐，但没人会用 |
| `platform_spec.py` 平台适配器 | **无示例** | 只有测试 |
| `resources.py` 资源拦截 | 示例全部传 `False` | 等于没演示 |
| `api_discovery.py` | 1 个示例（06） | 覆盖了 |
| `headers.py` | 1 个示例（05） | 覆盖了 |

**结论：** 「脚本有没有用」和「agent 会不会用」是两件事。

一个模块再有用，如果没有示例，agent 就会绕过它，自己重写。

### 2026-11 追加修复（子代理评测后）

子代理在 biquge 上实测：`js_bundle.hunt_api` 返回 **0 baseURL、0 接口**，但页面的 `data.js` 里明明写着
`getJson(BASE + "/data/" + name)` 和 `fetch(APIBI + "/api/" + path)`。

| 问题 | 修复 |
|---|---|
| 只认字面量路径，不认「常量 + 拼接」 | 新增 `extract_js_constants`，支持 `var X = "..."` 和 `var X = ... || "默认值"` |
| 常量噪音（XML 命名空间、npm 包名、base64 表、广告链接） | 收紧 `_looks_like_url_or_path`，只收 URL 或 `/路径`，排除 `?`/`#` |
| `_http_get` 用裸 `curl_cffi`，与红线矛盾 | 改为复用 `AntiRiskHttpClient`，失败回退 urllib |

**实测对比：**

```text
biquge  修复前：0 接口
        修复后：2 接口（https://apibi.cc/api/、https://www.biquge.mom/data/）

B 站    修复后：JS 常量 0 噪音，/x/web-interface/popular 仍命中
```

**验证：** `pytest` 73 passed（新增 5 个用例：常量提取、`|| 默认值`、拼接、常量不污染 baseURL、`_http_get` 走 `AntiRiskHttpClient`）。
