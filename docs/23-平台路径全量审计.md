# 23 · 平台路径全量审计与生产选型

> 目的：**对平台 X 测所有路径，保存方法，选出生产使用的最优方法。**
>
> 这篇不是“某个平台的结论”，而是一张可复用的审计表。
> 每接一个新平台，复制第 1 节的矩阵，逐条打勾；最后用第 3 节的评分卡做选型。
>
> 关键原则：**没有测过的路径，不能写“不可用”；没有达到验收标准的路径，不能写“生产可用”。**

---

## 0. 两个产出物

做完一个平台，必须留下两个文件：

| 产出 | 内容 | 存放位置 |
|---|---|---|
| **路径矩阵** | 每条路径的层级、登录、签名、耗时、成功率、字段口径、风险、结论 | `platforms/<platform>.md` 或本文附录 |
| **生产选型卡** | 主路径、兜底路径、回滚开关、验收数据、最后验证日期 | `platforms/<platform>.yaml` 或 `docs/22` 记录 |

只写“抖音用浏览器”不算完成；必须写清楚：

- 为什么不用另外 6 条路；
- 主路径的成功率、耗时、失效条件；
- 失效后切哪条；
- 哪条路是“能跑但口径不对”，不能混用。

## 1. 路径清单（逐条打勾）

| # | 路径 | 层级 | 需要登录 | 需要签名 | 典型耗时 | 本次结论 |
|---|---|---|---|---|---|---|
| 1 | 匿名 HTML（SSR） | L2 | 否 | 否 | 毫秒 | ☐ 测过 / ☐ 未测 |
| 2 | 匿名 JSON API / REST | L1 | 否 | 否 | 毫秒 | ☐ |
| 3 | 匿名 GraphQL | L1 | 否 | 否 | 毫秒 | ☐ |
| 4 | 旧版 / 移动端 API | L1 | 可能 | 可能 | 毫秒 | ☐ |
| 5 | 分享页 / 公开主页 SSR | L2 | 否 | 否 | 毫秒 | ☐ |
| 6 | SSR 状态容器（`__NEXT_DATA__` / `__NUXT__` / `__INITIAL_STATE__`） | L2 | 否 | 否 | 毫秒 | ☐ |
| 7 | JS 包找接口（含全部动态 chunk） | L0 | 否 | 否 | 秒级（下载 JS） | ☐ |
| 8 | 登录态 HTTP（Cookie） | L1 | 是 | 可能 | 毫秒 | ☐ |
| 9 | 浏览器 XHR 拦截 | L3 | 可能 | 平台生成 | 秒级 | ☐ |
| 10 | 浏览器导出签名参数 → HTTP 重放 | L1（伪） | 是 | 是，但有 TTL | 毫秒 + 刷新成本 | ☐ |
| 11 | 官方开放平台 / 合作 API | L1 | 是 | 是 | 毫秒 | ☐ |
| 12 | App API / 私有协议 | L1 | 是 | 是 | 毫秒 | ☐ |
| 13 | DOM 解析 | L4 | 可能 | 否 | 秒级 | ☐ |
| 14 | 截图 / OCR | L4 | 可能 | 否 | 秒级 | ☐ |

> “测过”必须附证据：状态码、响应片段、字段值、耗时、时间。
> 只写“打不开”不算证据，要写“403 / 62 字节挑战页 / `need_login=true`”。

## 2. 单次探测记录模板

每条路径至少落一条 JSON：

```json
{
  "platform": "demo",
  "test_url": "https://example.com/profile/123",
  "path": "browser_xhr",
  "layer": "L3",
  "status": 200,
  "latency_ms": 2400,
  "login_required": true,
  "signature_required": false,
  "fields": {
    "followers": 36,
    "following": 45,
    "works": 43
  },
  "field_semantics": {
    "followers": "web.profile.follower_count",
    "following": "web.profile.following_count",
    "works": "web.profile.aweme_count"
  },
  "stop_reason": "completed",
  "evidence": "拦截 /aweme/v1/web/user/profile，status_code=0；浏览器标题与账号一致。",
  "tested_at": "2026-11-06"
}
```

必填字段：

- `path` / `layer`：这条结论属于哪条路；
- `status` / `latency_ms`：可比较；
- `login_required` / `signature_required`：决定能不能批量；
- `field_semantics`：数字到底是什么口径；
- `stop_reason`：`completed` / `login_required` / `blocked` / `rate_limited` / `captcha` / `signature_failed` / `parameter_error`；
- `evidence`：可复现的最小证据。

## 3. 生产选型评分卡

### 3.1 硬门槛（不满足直接淘汰）

| 门槛 | 要求 |
|---|---|
| **口径正确** | 字段定义与产品一致；`null` 不当 0；跨源不混用 |
| **成功率** | ≥95%（30 个目标 × 3 轮，或等价样本） |
| **稳定性** | 连续 3 天同一时段可复现，不出现“一次正常一次验证页” |
| **可维护** | 签名/选择器失效时有明确检测点和兜底 |
| **合规** | 只采公开可见数据；不绕验证码；频率合理 |

### 3.2 评分维度（1~5 分）

| 维度 | 5 分 | 3 分 | 1 分 |
|---|---|---|---|
| **成本** | 纯 HTTP，<500ms | 浏览器，2~5s | 人工/截图 |
| **依赖** | 无登录、无签名 | 登录 Cookie | 登录 + 运行时签名 |
| **稳定性** | SSR/公开 API | 登录态 API | DOM/加密页 |
| **风控风险** | 匿名低频 | 登录态低频 | 高频/易封号 |
| **维护成本** | 字段稳定 | 偶尔改版 | 每周变 |

**口径正确是 veto（一票否决）。** 速度再快，数字口径不对也不能做主路径。

### 3.3 选型结论格式

```yaml
platform: douyin
primary:
  path: browser_xhr
  layer: L3
  reason: "唯一验证过、口径与 Web 一致的路径"
  latency_ms: 2400
  success_rate: "待补：30 目标 × 3 轮"
  login_required: true
  signature_required: true
fallback:
  path: mobile_api
  layer: L1
  reason: "快，但数字口径不同，只做量级参考"
  latency_ms: 228
  allowed_for_product: false
rollback:
  env: SOURCE_MODE
  values: ["browser_xhr", "mobile_api", "dom"]
last_verified: "2026-11-06"
```

## 4. 决策规则

```text
先做口径正确的路径，再谈快不快。

L1 匿名 HTTP 通过口径 + 稳定性
 ├─ 是 → 选 L1，结束
 └─ 否 ↓

L1 登录 HTTP 通过
 ├─ 是 → 选 L1 + Cookie 池，结束
 └─ 否 ↓

L3 浏览器 XHR 通过
 ├─ 是 → 先上 L3 保底
 │        └─ 做签名剥离：导出运行时参数 → HTTP 重放
 │             ├─ 成功且 TTL 可接受 → 降回 L1
 │             └─ 失败 → 保持 L3，优化 profile 复用
 └─ 否 ↓

L2 SSR 状态 / L4 DOM
 ├─ 通过 → 选 L2/L4，标为“易碎路径”，加选择器兜底
 └─ 不通过 → 判定“当前不可做”，写清卡在哪一层
```

**不要为了“纯 HTTP”去逆算法。** 先让浏览器生成，再导出重放。
**不要为了“快”选口径不同的源。** 数字对不上，越快越危险。

## 5. 抖音样例（2026-11-06 实测）

| 路径 | 结果 | 口径 | 结论 |
|---|---|---|---|
| 匿名主页 HTML | 200，72KB `_$jsvmprt` 壳 | 无 | ❌ |
| 匿名分享页 | 200，72KB `_$jsvmprt` 壳 | 无 | ❌ |
| 匿名旧版移动 API | 200 JSON，228ms | 30 / 40 / 34 | ⚠️ 快，但与 Web 不一致 |
| 匿名 Web `profile/other` | 200 空 body | 无 | ❌ |
| 纯 HTTP + 登录 Cookie | 72KB `_$jsvmprt` 壳 | 无 | ❌ |
| 浏览器 + 登录 Cookie XHR | 36 / 45 / 43 | Web 口径 | ✅ 当前唯一正确路径 |
| 浏览器导出 `msToken` / `a_bogus` → HTTP 重放 | 未测 | 未知 | ⏳ 下一步 |
| App API / 开放平台 | 未测 | 未知 | ⏳ |
| `page.request` / CDP 直发 | 未测 | 未知 | ⏳ |

**结论：抖音目前只有“单账号、正确口径、L3 浏览器”被验证。**
**“大规模、轻量、快速复用”尚未验证；旧版移动 API 虽然 228ms，但口径不对，不能直接做主数据源。**

### 抖音要补的验收实验

1. 从浏览器导出一次完整请求（URL / headers / cookies / `msToken` / `a_bogus`）；
2. 用 `AntiRiskHttpClient` 重放 10 个不同主页；
3. 记录成功率、耗时、token TTL、验证码触发率；
4. 若成功率 ≥95%、TTL ≥10 分钟 → 可做 L1 批量；
5. 否则做浏览器池：一个持久化 profile，顺序访问 N 个主页，拦截 XHR；
6. 记录每主页耗时、连续访问多少触发验证码；
7. 用 `SOURCE_MODE` 保留 L3 兜底。

## 6. 快手样例（对比）

| 路径 | 结果 | 口径 | 结论 |
|---|---|---|---|
| 匿名 GraphQL | `result=2`、`userProfile=null` | 无 | ❌ |
| 登录态 GraphQL（`userId=eid`） | 200，229ms | `ownerCount.fan/follow/photo_public` | ✅ 当前最优 |
| REST `/rest/v/profile/get` | 200，`fans/follows` | 与 GraphQL 一致 | ✅ 可做交叉校验 |
| REST `/rest/v/profile/feed` | `result=21` | 无 | ❌ 不要用来数作品 |

**快手是“L1 登录态 HTTP”的正面例子：**
拿到接口后做签名剥离测试，确认不校验 `__NS_hxfalcon`，于是从 L3 降回 L1，229ms。

## 7. 失败回退分类

| `stop_reason` | 含义 | 是否回退 |
|---|---|---|
| `blocked` | 明确被封 / WAF 挑战 | ❌ 不回退，止损 |
| `rate_limited` | 429 / 限频 | ❌ 不回退，退避 |
| `captcha` | 验证码 / 人机 | ❌ 不回退，通知 |
| `login_required` | 缺登录态 | ⚠️ 补登录，不换路径硬试 |
| `signature_failed` | 签名校验失败 | ✅ 优先转浏览器 L3 |
| `parameter_error` | ID / 字段 / 参数错 | ⚠️ 先修参数，不是换路径 |
| `network` | 超时 / 连接失败 | ✅ 可回退/重试 |
| `not_found` | 404 / 目标不存在 | ✅ 可回退 |
| `empty` | 200 但空 body | ✅ 可回退，先判是否挑战页 |

**不要把“被拒绝”伪装成“成功返回空”。** 空数据必须带 `stop_reason`。

## 8. 验收清单

```text
[ ] 14 条路径逐条打勾，未测的写“未测”，不写“不可用”
[ ] 每条路径都有 status / latency / 登录 / 签名 / 字段口径 / 证据
[ ] 至少两条路径做过双跑校验（同目标、同时间窗）
[ ] 口径不同的源已标注，未混用
[ ] 主路径成功率 ≥95%（30 目标 × 3 轮或等价样本）
[ ] 连续 3 天可复现，不是单次侥幸
[ ] 有兜底路径和 SOURCE_MODE 回滚开关
[ ] 有失效检测点（401/result=2/验证码/空 body）
[ ] 有频率上限和停止条件
[ ] 记录最后验证日期和平台版本/页面版本
```

## 9. 可执行工具：`path_audit.py`

上面的矩阵不是只用来手填的。`tools/path_audit.py` 把 14 条路径变成一次可重复的跑批：

```bash
python tools/path_audit.py --config examples/platforms/bilibili_audit.yaml
# 只跑指定路径
python tools/path_audit.py --config ... --only anonymous_json,ssr_state
# 浏览器路径策略：auto（默认，装了 patchright 才跑）/ always / never
python tools/path_audit.py --config ... --browser always --headed
```

### 9.1 配置最小结构

```yaml
platform: demo
test_url: https://example.com/profile/123
uid: "123"

# 字段口径是硬门槛：缺一条就会被 veto
field_semantics:
  followers: "web.profile.follower_count"
  following: "web.profile.following_count"

endpoints:
  - path: anonymous_json          # 也可以是 login_http / mobile_api / anonymous_graphql
    name: relation
    url: https://api.example.com/relation
    params: {vmid: "{uid}"}
    risk_codes: {"-352": captcha, "-799": rate_limited}
    required_fields: [data.follower, data.following]
    fields: {followers: data.follower, following: data.following}

state_fields:                     # SSR 状态容器
  followers: user.follower
xhr_pattern: "/api/profile"       # 浏览器 XHR
xhr_fields:
  followers: data.follower
dom_fields:                       # DOM 兜底
  followers: {selector: ".fans .num", attr: text}
```

### 9.2 已实现 / 未实现

| 状态 | 路径 |
|---|---|
| **已实现探测器** | `anonymous_html`、`anonymous_json`、`anonymous_graphql`、`mobile_api`、`share_ssr`、`ssr_state`、`js_bundle`、`login_http`、`browser_xhr`、`signature_replay`、`dom` |
| **只给测法，不假装测过** | `open_platform`、`app_api`、`ocr`（以及任何没配 `endpoints` / `share_url` / `xhr_pattern` 的路径） |

未测路径在 `run_report.json` 和 `audit.md` 里统一是 `not_tested`，并附「怎么测」。
**工具不会把未测写成「不可用」。**

### 9.3 两个产出物

```text
runs/<platform>-<date>/
├─ run_report.json   # RunReport：total / ok / success_rate / failed_by_reason / coverage
└─ audit.md          # 14 条路径矩阵 + 评分卡 + 生产选型卡 + 验收清单
```

`audit.md` 的选型卡固定包含：

- `primary` / `fallback` / `rollback`（`SOURCE_MODE` 的取值）；
- `rejected`（每条为什么被淘汰）；
- `production_ready` 与 `acceptance_gaps`。

**单次审计的 `production_ready` 永远是 `false`。** 要变成 `true`，必须补齐：

- 主路径 30 目标 × 3 轮成功率 ≥95%；
- 连续 3 天同一时段可复现；
- 生产配置里的失效检测点与频率上限。

### 9.4 退出码与硬停

| 退出码 | 含义 |
|---|---|
| `0` | 审计完成（结论可能是「没有可用路径」，这不是执行失败） |
| `1` | 配置 / 参数错误 |
| `2` | 验证墙或明确封禁：截图 + 通知 + **不再尝试其他路径** |

命中 `captcha` / `blocked` 后，剩余路径全部标 `not_tested` 并注明「前置路径硬停」。
这是红线，不是可配置项。
