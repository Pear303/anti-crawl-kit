# 30 · 发布流程（CI → PyPI → GitHub Release）

> 目标：打一个 tag，自动完成「构建 → 发 PyPI → 建 GitHub Release」。
> 不需要在仓库里存 PyPI token，用 OIDC trusted publishing。

---

## 1. 一次性配置

### 1.1 PyPI：配置 trusted publisher

先注册 PyPI 账号并开启 2FA，然后二选一：

**项目还没在 PyPI 上创建过**（当前就是这种情况）：

1. 打开 <https://pypi.org/manage/account/publishing/>；
2. 在 **Pending publishers** 里点 **Add a new pending publisher**；
3. 填写：

| 字段 | 值 |
|---|---|
| PyPI Project Name | `anti-crawl-kit` |
| Owner | `Pear303` |
| Repository name | `anti-crawl-kit` |
| Workflow name | `release.yml` |
| Environment name | `pypi` |

首次成功发布后，这个 pending publisher 会自动转成正式项目的 trusted publisher。

**项目已经存在**：进入项目的 **Manage → Publishing**，添加同样的 trusted publisher。

> 这五项必须和 `.github/workflows/release.yml` 完全一致，大小写、文件名、environment 名都不能差。

### 1.2 GitHub：创建 `pypi` environment

打开 <https://github.com/Pear303/anti-crawl-kit/settings/environments>，点 **New environment**，名字填 `pypi`。

建议加一条部署保护规则：

- **Deployment branches and tags** → **Selected branches and tags**；
- 添加 **tag** 规则：`v*`。

这样只有 `v*` tag 能触发发布，普通分支和 PR 碰不到 PyPI。

> environment 不手动建也能跑（GitHub 会自动创建无保护规则的 environment），但不建议，等于少了一道闸。

### 1.3 可选：保护 tag

仓库 **Settings → Tags → New rule**，pattern 填 `v*`，限制谁能创建/删除版本 tag。

## 2. 正常发版

### 2.1 改版本号

版本唯一来源是：

```text
src/anti_crawl_kit/__init__.py
```

```python
__version__ = "0.11.0"
```

`pyproject.toml` 用的是 `dynamic = ["version"]`，不用改。

顺手更新 README / 文档里的版本相关描述（如果有）。

### 2.2 本地验证

```powershell
python -m ruff check src tests
python -m pytest tests -q
python -m build
```

至少确认 `pytest` 全绿、wheel 能构建。

### 2.3 提交并推送

```powershell
git add -A
git commit -m "chore: v0.11.0"
git push origin main
```

### 2.4 打 tag 并推送

```powershell
git tag -a v0.11.0 -m "v0.11.0"
git push origin v0.11.0
```

**这一步就是发布开关。** 推送 tag 后，`.github/workflows/release.yml` 会自动：

```text
checkout tag
→ 校验 tag 与 __version__ 一致
→ python -m build（sdist + wheel）
→ 干净 venv 里装 wheel，验证 ack-report / ack-ui 入口
→ pypa/gh-action-pypi-publish 发 PyPI（OIDC）
→ gh release create 建 GitHub Release，附上 sdist/wheel
```

### 2.5 观察结果

- Actions：<https://github.com/Pear303/anti-crawl-kit/actions/workflows/release.yml>
- PyPI：<https://pypi.org/project/anti-crawl-kit/>
- Release：<https://github.com/Pear303/anti-crawl-kit/releases>

三个 job 全绿才算发布完成：

```text
build            success
publish to PyPI  success
GitHub Release   success
```

## 3. 手动补发

用于「tag 已经推了，但 PyPI 那步失败」或者「想给已存在的 tag 补产物」。

1. 打开 Actions → **release** → **Run workflow**；
2. 输入 tag，例如 `v0.10.0`；
3. 运行。

行为：

- 重新构建并校验版本；
- PyPI 用 `skip-existing: true`，已存在的文件会跳过，不会报错；
- GitHub Release 已存在时走 `gh release upload --clobber`，只更新产物，不重复创建。

> PyPI 不允许覆盖已发布的同版本文件。如果代码变了但版本没变，只能发新版本，不能靠重跑修好。

## 4. 失败排查

| 现象 | 原因 | 处理 |
|---|---|---|
| `tag v0.11.0 与 __version__ 0.10.0 不一致` | 忘了改版本 | 改 `__init__.py`，提交后删掉本地 tag 重打 |
| `invalid-publisher` / `Trusted publishing exchange failure` | PyPI 五项配置不匹配 | 核对 owner / repo / workflow / environment / 项目名 |
| `Environment pypi is not allowed` | environment 保护规则拦了 | 检查 tag 规则是否为 `v*`，或临时放开 |
| `File already exists` | 同版本重复发布 | 发新版本；`skip-existing` 只跳过完全相同的文件 |
| `--verify-tag` 失败 / `release not found` | tag 没推到远端 | `git push origin v0.11.0` |
| `id-token` 权限错误 | publish job 缺 `id-token: write` | 检查 job 的 `permissions` |
| wheel 装完 import 失败 | 打包漏文件 | 本地 `python -m build` 后在干净 venv 里装一遍 |

删 tag 重打的命令：

```powershell
git tag -d v0.11.0
git push origin :refs/tags/v0.11.0
# 改完版本、提交后再重新打
```

> 如果 tag 已经触发过 PyPI 发布，删 tag 不会删 PyPI 上的版本。

## 5. 本地预演

发版前想完全模拟 CI 的构建和安装：

```powershell
python -m build

$venv = "C:\Windows\Temp\opencode\venv-check"
python -m venv $venv
& "$venv\Scripts\pip.exe" install --quiet dist\anti_crawl_kit-0.11.0-py3-none-any.whl
& "$venv\Scripts\python.exe" -c "import anti_crawl_kit; print(anti_crawl_kit.__version__)"
& "$venv\Scripts\ack-report.exe" --help
& "$venv\Scripts\ack-ui.exe" --help
```

确认版本号、两个新入口、`LICENSE` / `NOTICE` 都在 wheel 里。

---

## 6. 安全边界

- 不使用长期 PyPI API token；OIDC 令牌只在 publish job 内有效。
- `id-token: write` 只给 `publish-pypi`，`build` 和 `github-release` 都没有。
- `pypi` environment 只允许 `v*` tag 部署。
- workflow 只在 tag push 和手动触发时运行，普通 push 不会发版。
- 发布前 CI 必须全绿；`release.yml` 自己不重复跑测试，默认你已经在 main 上验证过。
