# 27 · 技术验证路线（G0~G4）

> 对应 `v0.7.0`。目标：把「这个项目能不能做、成本多少、风险在哪」变成一份可复现的评估报告，而不是拍脑袋。

---

## 1. 五个关卡

| Gate | 名称 | 回答的问题 | 实现 |
|---|---|---|---|
| **G0** | 形态 | 数据在 HTML / SSR 状态 / JS 里？有没有验证墙、登录墙？ | `probe_url` / `classify_page` / `empty_shell` |
| **G1** | 路径 | 14 条路径里哪条可行？成本多少？ | `path_audit` + 评分卡 / `bench` |
| **G2** | 数据 | 字段全不全？能不能去重？增量是否生效？ | `data_contract` + `dom_extract` |
| **G3** | 稳定 | 连续跑 N 次稳不稳？并发会不会触发 429/验证码？ | `stability` / `ack-smoke` |
| **G4** | 工程 | 平台注册表/入口/cookie 有没有漂移？能不能接 agent？ | `ack-health` / `ack-mcp` |

每关四档：`PASS / WARN / FAIL / SKIP`。

---

## 2. 一条命令

```bash
ack-assess --config examples/assessments/books.yaml
ack-assess --config my_platform.yaml --out runs/assessment-myplatform
ack-assess --config my_platform.yaml --no-audit     # 跳过 G1，快速评估
```

输出：

```text
runs/assessment-<platform>/
├─ assessment.json   # 完整证据（每关 status/evidence/gaps）
└─ assessment.md     # 给项目决策看的一页纸
```

退出码：

| 码 | 含义 |
|---|---|
| 0 | `go` / `conditional_go` |
| 1 | `no_go` |
| 2 | 配置错误 |

## 3. 配置

```yaml
platform: myplatform
url: https://example.com/list

# G2：卡片 + 字段抽取
item_selector: article.card
field_selectors:
  title: {selector: "h3 a", attr: title}
  price: {selector: ".price"}

contract:
  name: myplatform
  id_field: title
  min_items: 20
  max_duplicate_ratio: 0.0
  max_missing_ratio: 0.0
  fields:
    title: {type: string, required: true, min_len: 2}
    price: {type: string, required: true, pattern: "^¥"}

incremental:
  mode: full          # full / incremental
  max_overlap_ratio: 1.0

# G3：稳定性
runs: 3
concurrency: 2
interval_ms: 300
min_success_rate: 1.0
count_tolerance: 0.1

# G1：路径审计（可选；不填则 SKIP）
audit_config: ../platforms/myplatform_audit.yaml
audit_only: [anonymous_html, dom]

# G4：健康体检（可选；不填则 WARN）
health_config: ../health/myplatform.yaml
module_root: ""
```

### 3.1 G2 的选择器能力

`dom_extract` 支持：

```
tag / .class / tag.class / tag.class1.class2
后代组合：h3 a / article.card h3
```

不支持 `>`、`+`、`~`、属性选择器。复杂页面用浏览器侧
`querySelectorAll`，或把抽取逻辑写成 `register_step`。

### 3.2 增量模式

| mode | 判定 |
|---|---|
| `full` | 允许全量重叠，只要求本次非空 |
| `incremental` | 重叠率 ≤ `max_overlap_ratio`，且新增 ≥ `min_new_items` |

静态整页列表用 `full`；有游标/时间戳的平台用 `incremental`。
**`full` 模式下报告会明确标注「增量未验证」**，不会假装通过。

## 4. 决策规则

### 4.1 状态

| 状态 | 含义 |
|---|---|
| `PASS` | 该关通过 |
| `WARN` | 能继续，但有已知缺口（例如单次审计、缺 health 配置） |
| `FAIL` | 该关阻断（验证墙、0 条、字段缺失、429 等） |
| `SKIP` | 没配置，无法验证（不能算通过） |

### 4.2 总决策

```
任一 FAIL              -> no_go
全部 SKIP              -> insufficient_evidence
全部 PASS              -> go
其余（有 WARN/SKIP）    -> conditional_go
```

### 4.3 评分

权重：G0 20 / G1 20 / G2 25 / G3 25 / G4 10。

- `PASS` 拿满分；
- `WARN` 拿一半；
- `SKIP` / `FAIL` 拿 0。

评分只用于横向比较项目，不替代决策规则。

## 5. 实测记录（2026-11-08）

### 5.1 正常链路：books.toscrape.com

```text
决策: CONDITIONAL_GO   评分: 85/100

[PASS] G0 形态: shape=ssr empty=False
[WARN] G1 路径: 已测 2 条，成功 2 条
[PASS] G2 数据: 20 条 / 去重后 20 / 重复率 0.0% / 新增 0
[PASS] G3 稳定: 3/3 成功，counts=[20, 20, 20]，blocked=0
[WARN] G4 工程: 未配置 health_config
```

缺口：

- 单次审计不能下生产可用结论（需双跑 + 不同时段）；
- 增量未验证（`mode=full`）；
- 健康体检未配置。

### 5.2 G4 通过：补 health 配置

```text
决策: CONDITIONAL_GO   评分: 80/100

[PASS] G0 / G2 / G3 / G4
[SKIP] G1（本次未配置 audit）
```

G4 通过条件：`ack-health` 无 FAIL + `mcp` 可导入。

### 5.3 负向验证：错误选择器

```text
决策: NO_GO           退出码 1

[FAIL] G2 数据: 条目数 0 < 要求 20
[FAIL] G3 稳定: 0/2 成功，counts=[]
```

这条用来证明评估器**不会把 0 条当成功**。

## 6. 怎么用这份报告

### 6.1 `go`

所有关卡 PASS。可以进入技术方案设计阶段，但仍需：

- 生产级存储/调度/监控；
- 合规审查（robots、平台条款、数据用途）；
- 长跑与容量测试（本评估只覆盖小样本）。

### 6.2 `conditional_go`

有已知缺口，但主路径可行。按 `next_actions` 补齐后再复评：

- G1 单次审计 → 双跑 + 不同时段；
- 增量未验证 → 提供游标字段或两次增量样本；
- G4 缺 health → 补 `ack_health.yaml`；
- G0 WARN → 先 `hunt_api` 找接口，或走浏览器 XHR/DOM。

### 6.3 `no_go`

至少一关 FAIL。不要把 FAIL 降级成 WARN 硬上；先解决：

- 验证墙/封禁 → 停，不要重试；
- 0 条/字段缺失 → 入口参数、选择器、登录态；
- 429 → 降并发/加间隔。

## 7. 接 MCP

`ack-mcp` 暴露 `assess_project`（异步 job）：

```json
{"tool": "assess_project", "arguments": {
  "config_path": "examples/assessments/books.yaml",
  "out_dir": "runs/assessment-books"
}}
```

然后：

```text
get_job(job_id) -> running / done / failed
get_job_result(job_id) -> {decision, score, gaps, next_actions, gates[]}
```

agent 拿到 `conditional_go` 后，可以按 `next_actions` 继续调用
`hunt_api` / `ack-health` / `recipe` 补证据。

---

## 8. 诚实边界

- **G1 单次审计永远不能证明「生产可用」**；报告固定给 WARN。
- **G2 的增量验证需要真实游标/两次样本**；`mode=full` 只验证去重与字段。
- **G3 是小样本**（默认 3 次）；容量、长跑、代理池不在本层。
- **G4 的健康体检需要真实平台模块**；练习站只能验证工具本身。
- 合规、账号安全、数据存储、调度监控不在本工具包范围内。
