# 05 · 排障手册

> 顺序：先定位「哪一层」（环境 / 行为 / 协议），再定位「哪一步」
> （启动 → 导航 → 登录 → 提取 → 关闭）。不要盲目改参数。

---

## 1. 浏览器启动失败

**症状：** `Executable doesn't exist` / `未找到任何可用的系统浏览器`

**排查：**

```bash
# 系统是否装了 Chrome / Edge
where chrome
where msedge

# patchright 是否可用
python -c "from patchright.sync_api import sync_playwright; print('ok')"
```

**处理：**

- `BrowserSession` 默认 `channel="chrome"` → `msedge` 降级。
- 都没有就装 Chrome；或显式传 `channel="msedge"`。
- 不要用 `p.chromium.launch()` 裸启动（会找内置 Chromium，通常没装）。

---

## 2. 页面空白 / 一直转圈

**症状：** `goto` 返回成功，但页面白屏、`document.readyState` 一直是 `loading`，
手动 Ctrl+Shift+R 后正常。

**根因（按概率）：**

1. patchright 与 Chrome 大版本不匹配（CDP 完成事件丢失）——最常见。
2. 网络抖动 / DNS / SSL 重置。
3. 代理配置错误。
4. 页面被资源拦截器误伤（JS 被 abort）。

**处理：**

```python
# 1) 检查 readyState
page.evaluate("() => document.readyState")

# 2) 自动 reload 自愈（BrowserSession 已内置，CDP 模式）
#    手动版：
page.reload(timeout=7000)

# 3) 确认版本
page.evaluate("() => navigator.userAgent")
#    对比 patchright 支持的 Chromium 大版本

# 4) 临时关闭资源拦截
BrowserSession(block_resources=False)
```

---

## 3. 登录页「系统繁忙」/ 扫码后秒过期

**症状：** 自动化窗口打开各平台创作者页提示「系统繁忙」，同一台机器手工
Chrome 打开完全正常。

**已排除项（不要重复排查）：**

- 服务器/后端故障
- Chrome 与驱动版本 gap（已对齐的情况下）
- 本机内存/CPU
- profile 锁
- PyInstaller 临时目录残留

**根因：** 平台对**自动化浏览器的登录环节**有独立风控。
手工浏览器不卡，是因为它早已是登录态，不走登录接口。

**处理：**

1. 冷却 30 分钟 ~ 数小时，不要连续登录。
2. 一次只登一个平台，优先测 profile 里已有登录态的平台。
3. 确认登录窗带上了完整反检测：
   - `STEALTH_JS` 已注入（`context.add_init_script`）
   - `CHROMIUM_ARGS` 完整
   - 不要用裸 patchright 启动登录窗
4. 仍不行 → 升级 patchright + 重打所有分发物。

---

## 4. 验证码反复出现 / 等不到消失

**排查：**

```python
from anti_crawl_kit.captcha import detect_captcha_page
print(detect_captcha_page(page, dom_detect_js=...))
```

- URL 检测命中但页面已正常 → 误报，检查关键词（`verify` 可能出现在正常 URL）。
- 页面有验证码但检测不到 → 补平台 DOM JS（参考 `captcha.py` 注册表）。
- 一直不消失 → 用户没完成 / 图片被拦截（`block_resources` 必须 False）。
- 通过后立刻又出现 → 频率太高，降频 + 冷却。

**不要：** 自动破解滑块；用 OCR 硬刚；无限重试。

## 5. 找不到元素 / 提取 0 条

**顺序排查：**

1. **页面真的加载了吗？** `page.title()`、`document.body.innerText[:200]`。
2. **是否在 iframe 里？** `page.frames`，需要 `frame_locator`。
3. **是否 Shadow DOM？** `locator("css=...")` 默认能穿透 open shadow root；
   closed shadow root 只能通过 JS 拿。
4. **选择器是否过期？** 用 `tools/dom_probe.py` 重新看候选结构。
5. **是否懒加载？** 需要先滚动到可视区域。
6. **是否登录墙？** 页面文案含「登录后查看」。
7. **是否验证码页？** 见第 4 条。

**兜底策略（重要）：**

```python
# 主选择器 + 兜底选择器
selectors = [".note-item", "section[class*='note']", "a[href*='/explore/']"]
for sel in selectors:
    items = page.locator(sel)
    if items.count() > 0:
        break
```

但兜底不能静默：最终 0 条要报错，并保存 HTML 快照。

## 6. 浏览器关不掉 / driver 进程残留

**症状：** 任务结束后 `node.exe` / `chrome.exe` 残留，内存持续上涨。

**根因：**

- `__enter__` 中途失败，`with` 不会调用 `__exit__`，`sync_playwright().start()`
  启动的 driver 子进程没 stop。
- 多个 channel 启动失败，产生孤儿浏览器进程。
- PyInstaller 打包后临时目录 `_MEI*` 累积。

**处理：**

- `BrowserSession` 已内置 `_cleanup_after_failed_enter()`。
- 业务代码用 `try/finally` 包住，确保 `session.close()`。
- 清理残留：

```powershell
Get-Process chrome, node -ErrorAction SilentlyContinue | Where-Object {
    $_.Path -like "*ms-playwright*" -or $_.CommandLine -like "*run-driver*"
} | Stop-Process -Force
```

- 清理 `%TEMP%\_MEI*`（PyInstaller 残留，实测可累积数 GB）。

---

## 7. 用户关窗后任务不退出

**症状：** 手动关闭采集浏览器窗口，任务继续等 100s 验证码 + 200s 登录，
多关键词场景还反复重开窗口。

**根因：** 等待循环没有存活探测；且 `page.is_closed()` 在进程死亡时可能假阴性。

**处理：**

- 所有等待循环入口调用 `ensure_alive(page)`。
- 不要用 `destroyed` 作为关闭特征（导航期间会误判）。
- 外层捕获 `BrowserClosedError`，只中止当前平台，不要杀整个任务
  （多平台并行时其他平台不受影响）。

## 8. 中文乱码 / `UnicodeEncodeError`

**症状：** Windows 控制台输出 `GBK` 编码错误；`print` 抛异常被外层 `except`
吞掉，导致「明明拿到数据却报失败」。

**处理：**

- 所有日志用 `[OK] / [WARN] / [FAIL]`，不要用 emoji / ✅ / ⚠️。
- 文件读写统一 `encoding="utf-8"`。
- 控制台临时切 UTF-8：

```powershell
chcp 65001
$env:PYTHONIOENCODING="utf-8"
```

- 库代码里避免裸 `print` 业务数据；用 `logging` 或 `safe_print` 包装。

## 9. 内存 / 磁盘暴涨

| 现象 | 根因 | 处理 |
|---|---|---|
| api 容器内存爬升 | SSE 订阅未清理 / 连接泄漏 | 检查 `finally` 里的 `await unsubscribe` |
| 浏览器内存 1GB+ | 页面未关、视频自动播放、缓存 | 关 tab、`--mute-audio`、限制缓存 |
| profile 目录 3GB+ | 缓存无限累积 | `--disk-cache-size=256MB`；定期清 Cache |
| `_MEI*` 占几 GB | PyInstaller 强杀残留 | 启动时清理 `%TEMP%\_MEI*` |
| 磁盘满 | 下载文件未清理、日志未轮转 | 下载完即移走；日志按天轮转 |

## 10. 视频/音频下载 403 或空文件

**根因：** CDN 防盗链校验 Referer。

**处理：**

```python
from anti_crawl_kit.headers import get_referer_for_url

referer = get_referer_for_url(video_url)
headers = {"Referer": referer} if referer else {}
```

- B站：`https://www.bilibili.com/`（注意部分节点是 `*.mountaintoys.cn`）
- 快手：`https://www.kuaishou.com/`
- 抖音：`https://www.douyin.com/`
- 下载要带 cookie（登录态）和 UA。
- 分片下载要支持 Range（206），并校验文件大小。

---

## 11. 接口 403 / 429 / 返回空

| 状态 | 可能原因 | 处理 |
|---|---|---|
| 403 | 缺 cookie / Referer / 签名 | 先用浏览器打开页面拿会话，再带 cookie 请求 |
| 429 | 频率超限 | 退避 30-60s；降并发；换 IP |
| 200 但 `data: null` | 签名错误 / 参数缺失 | 对比浏览器实际请求参数 |
| 200 但 HTML | 被重定向到验证页 | 检测验证码 / 登录墙 |
| 412 | 风控挑战（B站常见） | 降低频率，复用浏览器会话 |

**通用动作：** `classify_http_result()` → `should_fallback_to_browser` 为 True
就切浏览器，不要继续重试 HTTP。

---

## 12. 采集结果「静默变空」

这是最危险的故障：任务成功、条数 0、没有报错。

**必做的防御：**

1. 列表选择器命中 0 → 抛错，不要返回空列表。
2. 保存最近一次页面 HTML 快照（`output/debug/<platform>/`，限 20 份）。
3. 记录每个选择器的命中数。
4. 连续 3 次 0 条 → 告警。
5. 定期跑 `platform_health_check` 类脚本（本包可参考 `tools/dom_probe.py` 扩展）。
