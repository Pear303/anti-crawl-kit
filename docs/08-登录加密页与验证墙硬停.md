# 08 · 登录加密页 & 验证墙硬停

> 两个最常被问到的场景：
> **A. 页面加密、还必须登录，怎么快速拿到数据？**
> **B. 自动加载新内容时撞到人机验证，怎么停下并通知，而不是重试到死？**
>
> 答案不是「更厉害的破解」，而是**换数据源 + 设止损线**。

---

## 0. 先分清两种「停」

工作包里有两种验证码处理方式，**用途完全不同，不能混用**：

| 能力 | 行为 | 适用阶段 | 预算 | 结果 |
|---|---|---|---|---|
| `wait_for_captcha_and_login` | 检测到验证码后**等人**，轮询直到消失 | 首次登录 / 扫码 | 验证码、登录双时钟 | 继续采集 |
| `ChallengeGate` | 检测到验证码后**立即停**，截图 + 通知 + 抛异常 | 批量加载 / 翻页 / 详情 | 无（不等待） | 退出，人工介入 |

一句话：

- **登录阶段可以等**，因为用户本来就在场。
- **批量阶段不能等**，因为你不知道用户什么时候回来；空等只会烧预算，重试只会加深风控。

## 1. 场景 A：登录 + 加密页面

### 1.1 先判断「加密」加密了什么

| 形态 | 页面表现 | 你该做什么 |
|---|---|---|
| JS 解密后渲染 | `goto` 后先骨架屏，1~3s 后出内容 | 等渲染稳定，读 DOM / SSR 状态 |
| 接口签名（`a_bogus` / `x-s` / `w_rid` / `x-zse-96`） | 接口 403 / 签名错误 | **L3 拦截页面自己发的请求**，不要自己算 |
| 响应体加密 | XHR 返回密文，页面 JS 解密后渲染 | 拦截「解密后」的二次请求，或读 DOM |
| 字体混淆 | `innerText` 是乱码/错字，截图正常 | 截图 + OCR，或找原始 JSON 接口 |
| 图片分片 / 雪碧图 | 一张图被切成很多小块 | 按 CSS 背景位置拼接，或直接截图 |
| Canvas 渲染 | DOM 里只有 `<canvas>` | 截图 + OCR（最后手段） |

**核心原则：浏览器已经帮你解密了，你只需要在正确的时机、从正确的层拿数据。**

优先级仍然是：**L1 接口 > L2 SSR 状态 > L3 XHR 拦截 > L4 DOM**。
但「加密 + 登录」场景通常 L1 走不通，直接从 **L3** 开始最省时间。

---

### 1.2 五步流程

```text
① 持久化 profile → 人工登录一次
② 登录检测锚点（cookie + 页面元素，双确认）
③ 打开目标页前先注册 capture_responses
④ 等正文稳定（连续 N 次文本不变），不要固定 sleep
⑤ 落盘：text + html + state + api_responses
```

对应代码（完整版见 `examples/08_logged_in_encrypted.py`）：

```python
from anti_crawl_kit import (
    BrowserSession, ChallengeGate, LoginStatus, Notifier,
    wait_for_captcha_and_login, wait_for_stable_text,
)

login_js = open("examples/platforms/login_check_generic.js", encoding="utf-8").read()
gate = ChallengeGate(platform="xiaohongshu", notifier=Notifier())

with BrowserSession(headless=False, data_dir="./profiles/xhs") as page:
    # 1) 登录（有头，允许等）
    page.goto("https://www.xiaohongshu.com/")
    outcome = wait_for_captcha_and_login(
        page=page,
        check_login=lambda p: LoginStatus(
            bool(p.evaluate(login_js, isolated_context=False)), method="dom"
        ),
        login_timeout=240,
    )
    if not outcome.resolved:
        raise SystemExit(3)

    # 2) 注册拦截（必须在导航之前）
    captured = page.capture_responses("/api/sns/web/")

    # 3) 打开目标页
    page.goto("https://www.xiaohongshu.com/search_result?keyword=...")
    gate.check_or_stop(page)

    # 4) 等渲染稳定
    text = wait_for_stable_text(
        page, "section.note-item, .note-content",
        min_chars=80, stable_rounds=3, timeout=30, gate=gate,
    )

    # 5) 落盘
    print(text[:500])
    print("接口响应:", len(captured))
```

### 1.3 登录检测怎么写

**不要只判断 cookie 存在。** cookie 可能是过期的、别的账号的、或者平台已经改名的。

推荐「双确认」：

```python
def check_login(page) -> LoginStatus:
    # 快路径：关键 cookie
    cookies = {c["name"] for c in page.get_cookies()}
    has_cookie = "web_session" in cookies
    # 最终确认：页面锚点
    has_anchor = page.evaluate(
        "() => !!document.querySelector('.user-info, [class*=\"avatar\"]')",
        isolated_context=False,
    )
    return LoginStatus(bool(has_cookie and has_anchor), method="cookie+dom")
```

平台锚点参考：

| 平台 | cookie | 页面锚点 |
|---|---|---|
| B站 | `SESSDATA` | 顶栏头像 / `.user-avatar` |
| 小红书 | `web_session` | `.user-info` / 头像 |
| 知乎 | `z_c0` | 头像 / 「我的主页」 |
| 抖音 | `sessionid` | 右上角头像 |
| 快手 | `kuaishou.web.cp.api_st` + `passToken` + `bUserId` | 头像 / 「发布作品」 |
| 微博 | `SUB` | 昵称 / 头像 |

> 快手特别注意：**不要用 `kuaishou.server.web.st`**，那是旧值。生产上踩过「扫码成功但程序判定未登录」。

### 1.4 加密页的四个判断信号

| 信号 | 说明 | 动作 |
|---|---|---|
| `goto` 返回后正文 < 100 字，且持续增长 | 异步渲染 | `wait_for_stable_text` |
| `window.__INITIAL_STATE__` / `__NEXT_DATA__` / `__NUXT__` 有数据 | SSR 注入了明文 | L2 直接读 |
| Network 里有 JSON 响应，字段和页面一致 | 接口是明文 | L3 拦截 |
| DOM 文本乱码但截图正常 | 字体混淆 | 截图 OCR / 找接口 |

读 SSR 状态必须用**主世界**：

```python
state = page.evaluate(
    "() => window.__INITIAL_STATE__",
    isolated_context=False,   # ★ 默认是隔离世界，读不到页面变量
)
```

小红书还有一个坑：`__INITIAL_STATE__` 里含 `undefined` 字面量，Python `json.loads` 会失败。
正确做法是让 Playwright 直接序列化子对象，或 `JSON.stringify` 后再取。

---

### 1.5 登录加密页的常见坑

1. **登录后 URL 会变**：扫码成功可能跳回首页/创作者中心，采集前要重新 `goto` 目标页。
2. **二次导航又触发验证码**：`wait_for_captcha_and_login` 已处理「恢复后重导航再检测」，但重导航后仍可能再出验证码；批量阶段交给 `ChallengeGate`。
3. **内容在 iframe / shadow DOM**：`document.querySelector` 找不到。先 `page.frames` 找 iframe，或 `element.shadowRoot.querySelector`。
4. **正文选择器选到了整个 `body`**：动态计数、推荐位会一直变，`wait_for_stable_text` 永远不稳定。选**正文容器**，不要选 `body`。
5. **登录态过期**：接口 401 或 `login_js` 变 false。`ChallengeGate(stop_on_login=True)` 会直接停并通知，不会拿空数据继续跑。
6. **加密接口返回 200 但内容是密文**：说明你拦错了层。找页面解密后再次发起的请求，或直接读 DOM。

## 2. 场景 B：加载更多 + 验证墙硬停

### 2.1 状态机

```text
        ┌──────────────────────────────┐
        │  LOAD（滚动 / 点「加载更多」） │
        └──────────────┬───────────────┘
                       ↓
              ┌─────────────────┐
              │ ChallengeGate   │──命中──→ 截图 + HTML + meta
              │ 检查验证墙       │          ↓
              └────────┬────────┘      通知（控制台/桌面/webhook）
                       │ 未命中          ↓
                       ↓              抛 ChallengeDetected
              ┌─────────────────┐          ↓
              │ 等待新内容       │      退出码 2（不重试）
              └────────┬────────┘
                       ↓
              ┌─────────────────┐
              │ 数量是否增长？   │──连续 N 轮不增长──→ 正常停止（0）
              └────────┬────────┘
                       │ 增长
                       └──→ 下一轮
```

### 2.2 最小代码

```python
from anti_crawl_kit import (
    BrowserSession, ChallengeDetected, ChallengeGate,
    LoadMoreDriver, Notifier,
)

gate = ChallengeGate(
    platform="xiaohongshu",
    notifier=Notifier(webhook="https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=xxx"),
    snapshot_dir="output/challenge",
)

with BrowserSession(headless=False, data_dir="./profiles/xhs") as page:
    page.goto("https://www.xiaohongshu.com/search_result?keyword=...")
    gate.check_or_stop(page)

    driver = LoadMoreDriver(
        page,
        item_selector="section.note-item",
        gate=gate,
        max_rounds=20,
        idle_rounds=3,
        wait_after=1.2,
    )
    try:
        result = driver.run()
        print(result.item_count, result.stopped_reason)
    except ChallengeDetected as exc:
        print("已停止：", exc.info.kind, exc.info.reason)
        raise SystemExit(2)
```

「加载更多」按钮版：

```python
driver = LoadMoreDriver(
    page,
    item_selector=".article-item",
    gate=gate,
    click_selectors=("text=加载更多", "button.load-more"),
    max_rounds=30,
)
```

> `click_selectors` 按顺序尝试；都点不到就退化为滚动。适合「按钮有时出现、有时是无限滚动」的页面。

### 2.3 通知怎么配

**控制台 + 日志**永远开启，不需要配置。
其他渠道按需：

| 渠道 | 配置 | 说明 |
|---|---|---|
| 企业微信 | `AC_KIT_NOTIFY_WEBHOOK=https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=...` | 自动识别，发 text 消息 |
| 飞书 | `AC_KIT_NOTIFY_WEBHOOK=https://open.feishu.cn/open-apis/bot/v2/hook/...` | 自动识别 |
| 钉钉 | `AC_KIT_NOTIFY_WEBHOOK=https://oapi.dingtalk.com/robot/send?access_token=...` | 自动识别 |
| Slack | `AC_KIT_NOTIFY_WEBHOOK=https://hooks.slack.com/services/...` | 自动识别 |
| 自定义 | 任意 URL | 发 `{"title","text","payload"}` |
| 桌面通知 | `AC_KIT_NOTIFY_DESKTOP=1` | Windows Toast / macOS / Linux |
| 提示音 | `AC_KIT_NOTIFY_SOUND=1` | 默认开 |

代码里直接传：

```python
notifier = Notifier(
    webhook="https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=xxx",
    desktop=True,
    sound=True,
)
```

通知失败不会影响主流程（所有渠道 best-effort）。
如果 webhook 挂了，至少还有控制台横幅 + 日志 + 桌面通知。

### 2.4 现场三件套

每次硬停都会在 `output/challenge/` 下留：

```text
20261104-153012-123_captcha.png    # 整页截图（看验证码长什么样）
20261104-153012-123_captcha.html   # 页面 HTML（看 DOM 特征/是否改版）
20261104-153012-123_captcha.json   # 结构化现场（URL/状态/原因/时间）
```

`meta.json` 示例：

```json
{
  "detected": true,
  "kind": "captcha",
  "reason": "dom:.geetest_widget",
  "url": "https://www.xiaohongshu.com/search_result?keyword=...",
  "status": null,
  "title": "小红书 - 你的生活指南",
  "platform": "xiaohongshu",
  "screenshot": "output/challenge/20261104-153012-123_captcha.png",
  "html": "output/challenge/20261104-153012-123_captcha.html",
  "meta_path": "output/challenge/20261104-153012-123_captcha.json",
  "at": "2026-11-04T15:30:12"
}
```

默认保留最近 20 组，自动清理旧的。需要留证据时把 `max_snapshots` 调大。

### 2.5 为什么不能重试

| 重试的后果 | 说明 |
|---|---|
| 风控评分累计 | 很多平台是「行为累计分」，越撞越深，最后从「待验证」变「封禁」 |
| 验证码不是网络错误 | `goto` 重试对验证码无效，只会刷新出一个新的验证码 |
| 登录态可能被踢 | 高频重试会触发「账号异常」，把原本有效的登录态弄失效 |
| 浪费预算 | 每轮重试都带退避，几分钟就没了，还拿不到数据 |

**正确动作：**

1. 立即停（`ChallengeGate` 已做）。
2. 人工打开浏览器完成验证。
3. 冷却 30~60 分钟（高风控平台）。
4. 降速/减量后再跑；连续两次触发就换时间段。

---

### 2.6 退出码与续跑

| 退出码 | 含义 | 上层调度器该怎么做 |
|---|---|---|
| 0 | 正常停止（no_growth / max_rounds） | 记录结果，继续下一个任务 |
| 2 | 验证墙/风控墙 | **不要自动重跑**；告警，等人工 |
| 3 | 登录/验证码等待超时 | 告警，让用户重新登录 |
| 4 | 浏览器被关闭 | 视为用户取消，不重跑 |
| 130 | Ctrl+C | 视为用户取消 |

续跑原则：

- 用**已采集 ID 去重**（`note_id` / `bvid` / `aweme_id`），不要从头再采。
- 续跑前先确认账号正常（手动打开目标页，不触发验证）。
- 通知去重：同一 URL 在 10 分钟内只发一次（可在调度器层做，避免 webhook 刷屏）。

### 2.7 验收清单

上线前手动验证一遍：

```text
[ ] 手动触发一次验证码（或访问一个必出验证的页面）
    → 10s 内停止
    → 控制台出现横幅
    → webhook/桌面通知收到
    → output/challenge/ 有三件套
    → 进程退出码为 2
[ ] 正常列表：连续 3 轮不增长后停止，退出码 0
[ ] 关掉浏览器窗口：10s 内退出，退出码 4
[ ] 登录态过期：停止并通知，退出码 2
[ ] 连续跑 3 次：不重复通知、不产生重复数据
```

## 3. 两个场景怎么组合

一个完整的「登录 → 列表 → 详情」采集器：

```text
启动
 ├─ 打开目标站，wait_for_captcha_and_login（首次登录，允许等）
 ├─ 创建 ChallengeGate(stop_on_login=True)
 ├─ 列表页：LoadMoreDriver(gate=gate).run()
 │    ├─ 每轮前后 gate.check_or_stop
 │    └─ 命中 → 截图/通知/退出 2
 ├─ 对每个详情：goto + gate.check_or_stop + wait_for_stable_text
 └─ 落盘 + 记录已采集 ID
```

**关键：`gate` 要贯穿整个生命周期，不能只在列表页用。**
详情页、翻页、点击「展开」都可能触发验证码。
