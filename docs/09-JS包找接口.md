# 09 · 从 JS 包里找真实接口

> 一句话：**页面 HTML 里没数据，不代表要上浏览器。先看它加载的 JS 包，接口大概率就写在里面。**
>
> 这是「零浏览器」路线最划算的一招：比渲染快 10~100 倍，比逆签名省几天。

---

## 0. 什么时候该用这招

出现下面任意两条，就优先查 JS 包，而不是直接开浏览器：

| 信号 | 说明 |
|---|---|
| HTML 里数据是空的 | 数字是 `<p></p>`、列表只有骨架屏 |
| 页面只有一个 `<script src>` | 典型 SPA 壳，数据全靠 JS |
| 数字/列表在 `goto` 后 1~3s 才出现 | 前端 XHR 拉的 |
| 接口 URL 没有 `sign` / `a_bogus` / `w_rid` / `x-s` | 不需要运行时签名，HTTP 直连有戏 |
| 接口只需要登录 cookie | 最适合这招 |

**反例（别浪费时间）：**

- 接口参数由 WASM / 混淆代码计算；
- 请求头必须带 JS 生成的签名；
- 强风控，HTTP 直连稳定 403 / 429。

这三种情况回到浏览器拦截（`examples/04_intercept_api.py`），不要硬逆。

## 0.5 先分清三类 JS，别搜错文件

| 类型 | 常见文件名 | 里面有什么 | 找什么去这里 |
|---|---|---|---|
| **数据层** | `data.js` / `api.js` / `service.js` | baseURL、接口路径、响应字段 | **找接口** |
| **渲染层** | `reader.js` / `ui.js` / `index.js` | DOM id、选择器、填充逻辑 | 找选择器 |
| **框架层** | `vendor.js` / `runtime.js` | React/Vue 运行时 | 不用看 |

**典型错误：** 在 `data.js` 里搜 `ch-title`（DOM id），搜不到就以为没有接口。
`ch-title` 在 `reader.js`，`data.js` 只管「从哪来 + 长啥样」。

### 最稳的入口：数据形状，不是文件名

文件名像 `data/api/service` 是好起点，但不保证。真正可靠的锚是：

1. **数据形状**：搜 `parseChapter` / `parseItem` / `d.txt` / `d.title`，看它读什么字段；
2. **请求动词**：从 parse 的调用方往上找 `fetch(` / `axios` / `.get(` / `request({url:`;
3. **基址变量**：`BASE` / `API` / `apiUrl` / `baseURL`。

顺序是「**形状 → 接口 → 主机**」，不是「文件名 → 猜接口」。

## 1. 五步流程

```text
① 抓 HTML（requests 即可，不用浏览器）
② 提取所有脚本入口（script src + modulepreload），递归跟进动态 chunk
③ 在 JS 里搜 baseURL / .get("/xxx") / 字段名
④ 拼出完整接口 URL
⑤ 带登录 cookie 直接请求，验证返回 JSON
```

对应命令：

```bash
# 一条命令走完 ①~④
python tools/js_api_hunt.py \
    --url "https://目标站/页面" \
    --cookie "关键cookie=xxx" \
    --field fansNum \
    --field subscribeNum
```

常用参数：

| 参数 | 作用 |
|---|---|
| `--filter popular` | 只显示路径/字段含关键字的候选 |
| `--api-host api.bilibili.com` | 接口域名和页面域名不同时，用它重拼 |
| `--limit 0` | 显示全部候选（默认 30 条） |
| `--loose` | 额外抓孤立的 `"/xxx"` 字符串（噪音大） |
| `--no-fetch` | 只列 `<script src>`，不下载 JS |
| `--browser auto` | 静态只发现 ≤2 个 JS 时，自动用浏览器枚举全部资源（默认） |
| `--browser always` | 总是用浏览器枚举；SPA / 动态 import 必用 |
| `--browser never` | 只用 HTTP，不启动浏览器 |
| `--max-scripts 80` | 最多下载多少个 JS（默认 80） |
| `--no-all-chunks` | 不递归 JS 里的动态 chunk（只扫入口） |
| `--html page.html --base-url ...` | 分析本地保存的 HTML |

输出会直接给你：

```text
── baseURL ─────────────────────────────────────
  /my
    来源: https://目标站/static/js/main_6a120aa.js
    上下文: ...baseURL:"/my",withCredentials:!0...

── 接口候选 ────────────────────────────────────
  [GET] https://目标站/my/dynamic_num
    原始路径: /dynamic_num
    来源: https://目标站/static/js/main_6a120aa.js
    上下文: ...c.prototype.getUserInfo=function(){a["default"].get("/dynamic_num")...

API 域名: api.example.com（候选接口若 404，用 --api-host 重拼）
```

## 2. 完整案例：百家号侧边栏三个数字

> 这个案例把「HTML 空壳 → JS 找接口 → 零浏览器拿数据」走了一遍。
> 平台会改版，接口和文件名会变，但方法不变。

### 2.1 现象

`https://www.baidu.com/my/index` 的 HTML 里：

- 用户名、`bsToken` 在 `<!--s-data:{...}-->` 里；
- 动态 / 关注 / 粉丝三个数字是空的 `<p>`；
- 页面只加载一个 `main_6a120aa.js`。

服务端**没有**下发数字，数字是前端 JS 拉的。

### 2.2 第一步：抓 HTML

```python
import requests

html = requests.get(
    "https://www.baidu.com/my/index",
    headers={"User-Agent": "Mozilla/5.0 ... Chrome/131.0.0.0 ..."},
    cookies={"BDUSS": "..."},
    timeout=15,
).text
```

### 2.3 第二步：下载 JS（防盗链 403 怎么办）

直接请求 CDN 上的 JS 可能返回 403。补两个头即可：

```python
js = requests.get(
    js_url,
    headers={
        "User-Agent": "Mozilla/5.0 ... Chrome/131.0.0.0 ...",
        "Referer": "https://www.baidu.com/my/index",   # ★ 关键
    },
    cookies={"BDUSS": "..."},
    timeout=15,
).text
```

> 防盗链看的是 `Referer`，不是 cookie。先补 Referer，再考虑 cookie。

### 2.4 第三步：JS 只有 152 字节？

那是**加载器**，不是业务代码。它里面会用 `import()` / `document.write` / 字符串拼出真正的 chunk。

处理方式：

- 搜 `.js` 字符串，找 `chunk` / `main` / `index` / `static/` 关键字；
- 用 `urljoin(加载器URL, 相对路径)` 拼出二级地址；
- 继续下载。

`tools/js_api_hunt.py` 已自动做这一步（`--no-follow-loaders` 可关）。

### 2.5 第四步：在 JS 里搜什么

按优先级：

| 搜什么 | 能拿到什么 |
|---|---|
| `baseURL` / `baseUrl` / `base_url` | 请求客户端的前缀，如 `"/my"` |
| `.get("/` / `.post("/` | 接口路径，如 `"/dynamic_num"` |
| `fetch("/` / `axios("/` | 同上 |
| `withCredentials` | 是否带 cookie（`true` 表示必须登录） |
| 字段名（`fansNum` / `subscribeNum` / `dynamicNum`） | 数据来自哪个接口、哪个对象 |

百家号的实际代码（压缩后）：

```js
c.prototype.getUserInfo = function() {
  a["default"].get("/dynamic_num").then(function(e) {
    0 === e.data.status && t.data.set("bjhInfo", e.data.data)
  })
}
```

配合前面的 `baseURL:"/my"`，拼出：

```text
GET https://www.baidu.com/my/dynamic_num
```

### 2.6 第五步：验证

```python
r = requests.get(
    "https://www.baidu.com/my/dynamic_num",
    headers={"User-Agent": "...", "Referer": "https://www.baidu.com/my/index"},
    cookies={"BDUSS": "..."},
    timeout=15,
)
data = r.json()["data"]
print(data["dynamicNum"], data["subscribeNum"], data["fansNum"])
```

返回里通常还带 `uk` 和各页跳转 URL，可以顺手做账号标识。

### 2.7 结果

- 零浏览器、零 Chromium、零 Playwright；
- 单次请求 < 300ms；
- 只要 cookie 有效，稳定返回。

## 3. 六个高频坑

### 3.1 只判断「HTML 里有数字」不够

数字可能在：

- `<!--s-data:{...}-->` 注释里的 JSON（服务端注入）；
- `<script>window.__INITIAL_STATE__=...</script>`；
- 空 `<p>` + 前端 XHR。

先看 HTML 里有没有，再决定要不要查 JS。

### 3.2 baseURL 是相对路径

`baseURL:"/my"` 要拼成 `https://www.baidu.com/my`，不是 `https://www.baidu.com/my/my`。

规则：

```text
绝对 baseURL（https://api.x.com） → 直接拼
以 / 开头（/my）                 → origin + baseURL
相对路径（api/）                 → urljoin(页面URL, baseURL)
```

### 3.2.1 接口域名 ≠ 页面域名（最容易 404 的地方）

页面在 `www.bilibili.com`，JS 里写的是：

```js
ru.request({url:"/x/web-interface/popular",method:"GET"})
```

但真实接口在 `api.bilibili.com`。只按页面 origin 拼会得到
`https://www.bilibili.com/x/...` → **404**。

处理方式：

1. 工具会打印 `API 域名: api.bilibili.com`（从 JS 里的 `//api.xxx.com/` 提取）；
2. 加 `--api-host api.bilibili.com` 重拼；
3. 或者直接在浏览器 Network 面板看一次真实请求的域名。

B 站实测：

```bash
python tools/js_api_hunt.py \
    --url "https://www.bilibili.com/v/popular/all" \
    --filter popular \
    --api-host api.bilibili.com
```

得到：

```text
[GET] https://api.bilibili.com/x/web-interface/popular
      原始路径: /x/web-interface/popular
      上下文: ...ru.request({url:"/x/web-interface/popular",method:"GET",params:{ps:r,pn:o}})...
```

然后直接请求就拿到数据：

```python
from anti_crawl_kit.http import AntiRiskHttpClient

c = AntiRiskHttpClient("bilibili")
r = c.get_json(
    "https://api.bilibili.com/x/web-interface/popular",
    params={"ps": 5, "pn": 1},
    headers={"Referer": "https://www.bilibili.com/v/popular/all"},
)
print(r.data["data"]["list"][0]["bvid"])
```

**判断技巧：** JS 里出现 `//api.` / `//open.` / `//gateway.` 前缀的域名，
大概率就是接口域名；页面域名只负责渲染。

---

### 3.3 `withCredentials: true` = 必须带 cookie

看到这个，说明接口依赖登录态。用 `requests` 时要把浏览器里的 cookie 原样带上。

**不要只带一个 cookie。** 平台通常要 2~4 个（如 `BDUSS` + `STOKEN` + `PTOKEN`）。最稳的方式是从浏览器 profile 里导出，或让浏览器发一次请求、从 `Network` 里复制 `Cookie` 头。

### 3.4 字段名是 camelCase

JS 里是 `fansNum`，不是 `fans_num`；是 `subscribeNum`，不是 `subscribe`。

搜的时候用**页面展示文案反推**：

| 页面文案 | 可能的字段名 |
|---|---|
| 粉丝 | `fansNum` / `fansCount` / `followerCount` |
| 关注 | `subscribeNum` / `followCount` / `followingCount` |
| 动态 | `dynamicNum` / `postCount` / `feedCount` |
| 作品 | `worksCount` / `videoCount` / `awemeCount` |

不确定就多传几个 `--field`。

### 3.5 接口路径是拼接出来的

JS 里常见两种：

```js
// A. 字面量 + 变量
"/user/" + id + "/stats"

// B. 常量 + 字面量（最常见）
var BASE = String(SITE.DATA_BASE || "/data");
var APIBI = String(SITE.APIBI_HOST || "https://apibi.cc");
getJson(BASE + "/author-docs-" + bucket + ".json");
fetch(APIBI + "/api/" + path)
```

`js_api_hunt` 现在会：

- 提取 `BASE` / `APIBI` 这类常量，支持 `var X = "..."` 和 `var X = ... || "默认值"` 两种写法；
- 把 `BASE + "/..."` 拼成 `https://站点/data/`；
- 输出「前缀 + 变量」的形式。

如果只拿到前缀（如 `https://apibi.cc/api/`），下一步：

1. 在浏览器 Network 里看一次完整请求；
2. 或读常量附近的 `apibiGet` / `dataJson` 函数，看变量从哪来。

**实测（biquge.mom）：**

```text
JS 常量: 2 个（BASE=/data, APIBI=https://apibi.cc）
接口候选: 2 个
  https://apibi.cc/api/
  https://www.biquge.mom/data/
```

修复前这里是 **0 个**——因为正则只认 `.get("/x")` 字面量。

### 3.6 返回 200 但内容是密文

说明拦错层了。找页面**解密后**再发起的请求，或直接读 DOM。不要试图在 Python 里解密。

---

### 3.7 只扫一个 chunk，是最常见的「漏接口」原因

真实案例（某 SPA 平台）：

- 页面 HTML 只有 1 个入口 JS，其余 **20 个 chunk 全是动态 import**；
- 第一次只看了名字最相关的 `profile-xxx.js`，搜 `visionProfile` 没命中就停了；
- 后来枚举页面实际加载的 **21 个 JS**，才在 `profile-xxx.js` 里找到字段层级，在 `index-xxx.js` 里找到错误码含义。

教训：

1. **不要只扫一个 chunk。** 字段名可能在页面 chunk，接口定义在 `index` / `vendor` chunk，错误码处理又在另一个 chunk。
2. **不要只按文件名猜。** `profile-xxx.js` 不一定有接口；`index-xxx.js` 反而可能有请求封装。
3. **动态 chunk 名字可能不含 `chunk/main/index/vendor`。** `profile-Cgkt1CT6.js`、`workbench-Dojrq00F.js` 这类名字很常见。
4. **先看覆盖率，再看结论。** 工具输出里的「发现 N 个 / 扫描 M 个」如果 M < N，结论不可信。

`js_api_hunt.py` 现在会：

- 读 `<script src>` 和 `<link rel="modulepreload">`；
- 从任意 JS 里递归提取 `.js` 引用（不再只对 <3KB 的加载器生效）；
- 静态入口 ≤2 个时自动用浏览器枚举页面实际加载的全部资源（`--browser auto`）；
- 输出「发现 / 扫描 / 覆盖率」，覆盖率不足时给警告。

```bash
# SPA / 动态 import：强制浏览器枚举全部 JS
python tools/js_api_hunt.py --url "https://目标站/profile/123" \
    --browser always --max-scripts 80 --field ownerCount --field photo_public
```

> 只加载一次页面拿 JS URL，后续仍由 HTTP 下载分析。
> 这比「每页都开浏览器渲染」便宜得多，也比「只读 HTML 里的一个 script」可靠得多。

## 4. 什么时候该放弃，回到浏览器

| 情况 | 判断方法 | 该做什么 |
|---|---|---|
| 需要签名 | 请求头有 `a_bogus` / `w_rid` / `x-s` / `x-zse-96` | 浏览器拦截（L3） |
| 参数由 WASM 算 | JS 里有 `.wasm`、`WebAssembly.instantiate` | 浏览器拦截 |
| 强风控 | HTTP 直连稳定 403 / 429 / 验证码 | 浏览器 + 降频 |
| 接口在 Worker 里 | JS 里有 `new Worker(...)` | 浏览器拦截 |
| 数据在 Canvas | DOM 里只有 `<canvas>` | 截图 OCR |

**判断标准：先花 10 分钟查 JS，查不到再上浏览器。** 不要反过来。

## 5. 和现有工具的关系

| 工具 | 什么时候用 |
|---|---|
| `tools/js_api_hunt.py` | **本文**：HTML 空壳、接口在 JS 里 |
| `tools/dom_probe.py` | 页面已经有 DOM 数据，要找选择器 |
| `ApiDiscoverer` | 已经开了浏览器，要看页面实际发了哪些请求 |
| `examples/04_intercept_api.py` | 接口需要签名/cookie，必须让浏览器发 |
| `examples/05_http_only.py` | 已经知道接口，要批量拉 |

推荐顺序：

```text
HTML 有数据？
 ├─ 是 → dom_probe.py → L4 DOM
 └─ 否 → js_api_hunt.py
          ├─ 找到接口 + 不需要签名 → requests / curl_cffi（L1）
          ├─ 找到接口 + 需要签名   → 浏览器拦截（L3）
          └─ 找不到               → 浏览器 Network 面板 / dom_probe.py
```

## 6. 验收清单

```text
[ ] HTML 里确实没有目标数据（不是选择器写错）
[ ] 找到页面加载的全部 JS（script src + modulepreload + 动态 chunk）
[ ] 扫描覆盖率 100%，或已明确说明哪些 JS 没扫
[ ] JS 下载成功（403 时补了 Referer）
[ ] 加载器/动态 chunk 已跟进（不是只看入口 JS）
[ ] baseURL 拼接正确（没有重复 /my）
[ ] 接口带 cookie 请求返回 200 + JSON
[ ] 返回字段和页面显示对得上（数字、ID、URL）
[ ] 已做签名剥离测试（见 docs/22）
[ ] 连续请求 3 次不触发验证码
[ ] cookie 过期时能识别（401 / status != 0），不是静默返回空
```

## 6.5 退出码与进度

| 退出码 | 含义 | 下一步 |
|---|---|---|
| 0 | 找到至少一个接口候选 | 继续验证接口 |
| 1 | 没找到候选（正常业务结果） | 换 `--loose`、`--browser always`，或改看 DOM |
| 2 | 运行错误（页面/JS 抓取失败、参数错误） | 先修网络、URL 或文件路径 |

下载多个 JS 时，进度写到 stderr：`[hunt] 已扫描 12/60 个 JS`，不会污染
stdout 的候选列表。`ack-audit` 的 `js_bundle` 路径也会每 5 个脚本报一次进度，
长任务不会看起来像卡死。
