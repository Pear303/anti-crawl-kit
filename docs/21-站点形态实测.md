# 21 · 站点形态实测（43 站）

> 实测日期：2026-11-05
> 环境：Windows 11 / Python 3.13.3 / curl_cffi 0.15.0
> 方法：HTTP 直连，每站 1 次公开首页 GET，站间间隔 0.6s，不登录、不抓内容。

## 1. 为什么要先判形态

接新平台时最容易犯的错，是拿一份 HTML 直接写选择器，却没先看它是什么：

- 数据已经在 HTML 里（SSR）→ 写选择器就行；
- 数据在 `__NEXT_DATA__` / `__NUXT__`（SSR + 状态）→ 正则提 JSON 更便宜；
- HTML 只有 `<div id="app"></div>`（SPA 壳）→ 选择器永远 0 命中；
- 登录墙 / 验证码墙 / WAF → 写什么都没用。

**形态判断错了，后面所有努力都是浪费。**

`anti_crawl_kit.page_shape.classify_page_shape()` 把这件事变成一行代码：

```python
from anti_crawl_kit import classify_page_shape

shape = classify_page_shape(html, status=200)
print(shape.kind, shape.advice)
# ssr_state  数据在全局状态：HTTP 正则提取，或浏览器打开一次读变量。
```

## 2. 八种形态

| kind | 判据 | 下一步 |
|---|---|---|
| `ssr` | 可见文本 > 800 字，无状态容器 | 直接解析，不开浏览器 |
| `ssr_state` | 命中 `__NEXT_DATA__` / `__NUXT__` / `__INITIAL_STATE__` / `self.__next_f.push` 等 | HTTP 正则提取 JSON |
| `spa_shell` | 可见文本 < 200 字且有 ≥3 个外链脚本 | `js_api_hunt` 找接口 |
| `login_wall` | 可见文本 < 500 字且含「请登录 / 扫码登录」 | 持久化 profile + 人工登录 |
| `captcha_wall` | 含「安全验证 / 滑动验证 / 请完成验证」或 title 含 captcha | 硬停 + 通知 |
| `blocked` | 401 / 403 / 429 / 503 / 521 | 换代理或停 |
| `tiny` | body < 1000 字节 | 先确认网络 / DNS / 挑战页 |
| `unknown` | 以上都不命中 | `agent_probe` 深挖 |

分类顺序有讲究：**状态容器优先于「响应太短」**。Next.js / Nuxt 首屏 HTML 可能只有几百字节，但数据已经在里面。

## 3. 实测结果

### 3.1 SSR（13 站）

| 站点 | 状态 | 大小 | 备注 |
|---|---|---|---|
| 豆瓣 | 200 | 86 KB | 老牌 SSR，反爬温和 |
| 虎扑 | 200 | 271 KB | 社区列表 SSR |
| 博客园 | 200 | 74 KB | 文章列表 SSR |
| 简书 | 200 | 36 KB | 首页 SSR，详情页可能 SPA |
| B 站 | 200 | 164 KB | 首页 SSR，数据接口另走 API |
| 少数派 | 200 | 105 KB | SSR |
| 爱范儿 | 200 | 116 KB | SSR |
| 京东 | 200 | 191 KB | 首页 SSR，搜索页另说 |
| 苏宁 | 200 | 202 KB | SSR |
| 当当 | 200 | 144 KB | SSR |
| GitHub | 200 | 530 KB | SSR + 大量内联数据 |
| MDN | 200 | 120 KB | SSR |
| dev.to | 200 | 299 KB | SSR |

**结论：** 内容站和电商首页仍以 SSR 为主。能 HTTP 就不要开浏览器。

### 3.2 SSR + 状态容器（5 站）

| 站点 | 状态容器 | 大小 | 价值 |
|---|---|---|---|
| 小红书 | `__INITIAL_STATE__` | 165 KB（正常时） | HTTP 直接拿首屏笔记 JSON |
| 掘金 | `__NUXT__` | 78 KB | 文章列表在状态里 |
| 纵横中文网 | `__NUXT__` | 333 KB | 书籍列表在状态里 |
| 番茄小说 | `__INITIAL_STATE__` | 143 KB | 书籍列表在状态里 |
| Zillow | `__NEXT_DATA__` | 424 KB | 房源数据在状态里 |

**结论：** 这 5 站不需要浏览器就能拿结构化数据，比解析 DOM 稳得多。

### 3.2.1 怎么取：`extract_state()`

```python
from anti_crawl_kit import AntiRiskHttpClient, extract_state

response = AntiRiskHttpClient("demo").get_text("https://fanqienovel.com/")
result = extract_state(response.text)
if result.ok:
    home = result.data["home"]
    print(len(home["writerList"]), len(home["updateList"]))
```

番茄小说实测（2026-11-05，一次 HTTP GET，142 KB）：

```text
ok=True key=initial_state
home keys: serverRendered, noticeList, bannerList, writerList,
           editorList, weekList, boyList, girlList, subscribeList, ...
  writerList: 54 条（uid / cover_uri / name / introduction）
  updateList: 20 条（bookName / itemId / bookId / title / updateTime / author）
  editorList: 9 条（bookId / abstract / thumbUri / bookName / author）
  weekList:   8 条
```

**一次请求拿到 100+ 条结构化数据，不需要浏览器、不需要签名、不需要解析 DOM。**

### 3.2.2 提取不了的情况

掘金的 `__NUXT__` 是 Nuxt 2 的 IIFE：

```js
window.__NUXT__=(function(a,b,c,...){...;return {layout:"default",...}})(...)
```

这不是 JSON 坏了，是必须用浏览器求值。`extract_state()` 返回：

```text
ok=False key=nuxt error=js_expression
```

**对策：** 看到 `js_expression` 就不要硬解析，直接用 `BrowserSession` 打开页面读 `window.__NUXT__`。

### 3.2.3 接进 GenericCollector：状态优先，DOM 兜底

不需要手写 `extract_state`，配置两行即可：

```python
spec = PlatformSpec(
    name="fanqie-writers",
    start_url="https://fanqienovel.com/",
    card_selector="div.writer-card",     # DOM 兜底
    state_path="home.writerList",        # 状态主路径
    fields={
        "uid": FieldSpec(state_path="uid"),
        "name": FieldSpec(state_path="name"),
        "intro": FieldSpec(state_path="introduction"),
    },
)
```

流程：

```text
goto → wait_ready
  → page_shape 判定 ssr_state？
      是 → extract_state → pick_path(state_path)
           ├─ 拿到非空列表 → 直接返回（不滚动、不解析 DOM）
           └─ 拿不到       → 回退 DOM（含自适应兜底）
      否 → 直接走 DOM
```

实测（番茄小说，headless Chrome）：

```text
INFO [fanqie-writers] 状态命中 'home.writerList'，59 条
=== 结果：59 条 ===
{'uid': '4393263683600765', 'name': '空留', 'intro': '代表作《惜花芷》《惹金枝》'}
{'uid': '66292947550', 'name': '杀虫队队员', 'intro': '代表作《十日终焉》'}
{'uid': '104957777655', 'name': '三九音域', 'intro': '代表作《我在精神病院学斩神》'}
```

验证方式：把 `card_selector` 故意写成 `div.__no_such_card__`，仍然拿到 59 条
—— 证明走的是状态路径，DOM 从未命中。

**字段映射规则：**

| 配置 | 行为 |
|---|---|
| `FieldSpec(state_path="author.name")` | 按路径从状态项取值 |
| `FieldSpec()` | 用字段名本身作为 key |
| `FieldSpec(all=True)` | 值不存在时返回 `[]` 而不是 `None` |
| `state_extract=False` | 完全关闭状态优先，只走 DOM |

**什么时候不该用状态优先：**

- 状态里的字段和页面展示不一致（比如状态是原始数据，页面做了脱敏）；
- 只需要首屏之外的数据（状态里通常只有首屏）；
- 状态是 Nuxt 2 IIFE（`js_expression`），提取不了，自动回退 DOM。

### 3.3 SPA 壳 / 不明（7 站）

| 站点 | 状态 | 大小 | 说明 |
|---|---|---|---|
| 36 氪 | 200 | 25 KB | 无 title、无状态，需看 JS |
| 抖音 | 200 | 73 KB | 首页 SPA，接口需签名 |
| 快手 | 200 | 342 KB | 大体积 SPA |
| 今日头条 | 200 | 4.9 KB | 首屏壳 |
| 淘宝 | 200 | 90 KB | 登录/壳混合 |
| Amazon | 200 | 2.2 KB | 反爬页（title 为 `&nbsp;`） |
| CSDN | 521 | 2 KB | 源站 521（Cloudflare 回源失败） |

**结论：** 这些站不要直接写 DOM 选择器，先 `js_api_hunt` 或抓 XHR。

### 3.4 登录墙（2 站）

| 站点 | 形态 | 检测路径 |
|---|---|---|
| 知乎 | 200 + 45 KB SPA 壳 | 可见文本「请登录」→ `login_required` |
| 微博 | 200 + 47 字节 JSON | 短 JSON 登录协议 → `login_required` |

**结论：** 同一个 `stop_reason`，两种完全不同的检测路径。只查 HTML 文案会漏掉微博，只查 JSON 会漏掉知乎。

### 3.5 被拦截（7 站）

| 站点 | 状态 | WAF 指纹 | 特征 |
|---|---|---|---|
| 百度贴吧 | 403 | — | 「百度安全验证」 |
| Stack Overflow | 403 | Cloudflare | `Just a moment...` |
| eBay | 403 | — | Error Page |
| Product Hunt | 403 | Cloudflare | `Just a moment...` |
| Yelp | 403 | — | 空 body |
| TripAdvisor | 403 | DataDome | 436 字节 |
| Craigslist | 403 | — | `blocked` |

**结论：** 403 就是 403，不要在同一 IP 上重试。换代理或停。

### 3.6 不可达（9 站）

| 站点 | 返回 |
|---|---|
| Hacker News / Reddit / Wikipedia / Medium / Substack / Indeed / Glassdoor / V2EX | 约 150 字节连接错误 |
| 起点中文网 | 202 + 209 字节（反爬挑战，不是网络问题） |

前 8 个是本机网络环境不可达，不是站点问题。起点是**真的反爬**：202 + 空 body，容易被误判成「正常但短」。

## 4. 六个关键发现

### 4.1 风控是概率性的，单次探测不可靠

小红书第一次探测：200 + 165 KB + `__INITIAL_STATE__`，完全正常。
第二次探测：200 + 10 KB + 「安全验证」→ `captcha`。

同一 IP、同一 UA、间隔几分钟，结果完全不同。

**对策：** 风控站至少采样 3 次，用「多数结果」判断，不要拿一次 200 就当稳定。

### 4.2 状态容器比 DOM 更抗改版

小红书、掘金、纵横、番茄、Zillow 都把首屏数据塞进全局变量。
DOM 的 class 会改，`__INITIAL_STATE__` 的字段名改得慢得多。

**对策：** `ssr_state` 优先读状态，DOM 只做兜底。

### 4.3 WAF 指纹 ≠ 被拦截

Zillow 页面里有 PerimeterX 脚本，但返回 200 + 424 KB 正常内容。
`detect_waf()` 的语义是「站点用了什么防护」，不是「当前请求被拦」。

**对策：** `detection` 只在失败时记录，成功时不要拿它吓自己。

### 4.4 202 + 空 body 是挑战

起点返回 202 + 209 字节，旧版 `classify_http_result` 判 `ok`。
现在：`202 + body < 1000 + 非 JSON` → `blocked / challenge_202`。

### 4.5 正常页面里的 `signature` 不是签名失效

番茄、抖音首页的 JS bundle 里有 `signature` / `a_bogus` / `w_rid`。
旧版全文匹配把它们误判成 `signature_failed`。

**修复：** 只在响应 < 2000 字节时才判签名失败。大页面不可能是「签名错误」的短错误体。

### 4.6 长页面里的「请登录」不是登录墙

正常内容页底部常有「请登录」按钮。
**修复：** 只在可见文本 < 500 字时才判 `login_required`。

## 5. 对采集策略的影响

| 形态 | 默认策略 | 成本 |
|---|---|---|
| `ssr` | HTTP + DOM 选择器 | 最低 |
| `ssr_state` | HTTP + 正则提 JSON | 低 |
| `spa_shell` | `js_api_hunt` → 接口直连 | 中 |
| `spa_shell` + 签名 | 浏览器拦截 XHR | 高 |
| `login_wall` | 持久化 profile + 人工登录一次 | 一次性 |
| `captcha_wall` | 硬停 | 0（止损） |
| `blocked` | 换代理或停 | 0（止损） |

**默认顺序不变：HTTP > SSR 状态 > 接口 > 浏览器。**

## 6. 怎么复现

```bash
# 单站形态
python -c "from anti_crawl_kit import classify_page_shape; ..."

# 一站式探测（含形态）
python tools/agent_probe.py --url https://juejin.cn/ --field article --quick --no-fetch-js

# 输出示例
# decision: html_has_data
# summary : HTML 里包含目标字段（351 字符正文）｜形态=ssr_state
# next    : 数据在 SSR 全局状态：优先读 __NEXT_DATA__ / __INITIAL_STATE__ / __NUXT__

# SSR 状态提取（离线演示 + 真实站点）
python examples/15_state_extract.py
python examples/15_state_extract.py --live
```

批量雷达脚本没有放进工作包：它依赖具体站点清单，属于一次性研究工具。
需要时按本文第 2 节的判据重写一个即可，核心逻辑已经在 `page_shape.py` 里。

## 7. 局限

- 只测了首页，详情页/搜索页形态可能不同；
- 海外站点受本机网络影响，9 个不可达，不代表站点本身；
- 风控结果随时间、IP、UA 变化，本文数据只代表 2026-11-05 这一次；
- `classify_page_shape` 是启发式，不保证 100% 准确；它是「第一眼判断」，不是「最终结论」；
- `extract_state` 不支持 Nuxt 2 IIFE 和 Next.js App Router 的 RSC 流（返回 `js_expression`），这两类必须用浏览器求值。
