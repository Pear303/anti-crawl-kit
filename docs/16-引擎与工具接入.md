# 16 · 引擎与工具接入（P1–P3）

> 这份文档回答一个问题：**调研出来的东西，具体怎么接进现有工作包。**
>
> 原则：不替换默认栈，只增加「可选后端」和「诊断能力」。
> 所有接入都必须是**可选依赖**，不装也能跑。

---

## 接入总览

| 优先级 | 项目 | 接入方式 | 是否改默认栈 |
|---|---|---|---|
| P1 | camoufox | 新增可选引擎 `engine="camoufox"` | 否 |
| P2 | rebrowser 检测清单 | 补进 `docs/02` + `tools/detector_check.py` | 否 |
| P2 | js-reverse-mcp | 外部 MCP 工具，写进工作流 | 否 |
| P3 | pydoll | 评估 + 最小示例，暂不集成 | 否 |
| P3 | Scrapy / Crawlee | 组合架构，做调度层 | 否 |

## P1 · camoufox：第二引擎

### 1.1 什么时候用

| 场景 | 用 patchright | 用 camoufox |
|---|---|---|
| 目标站只做通用风控 | ✅ | 可选 |
| 目标站针对 Chromium 自动化 | 效果差 | ✅ |
| 需要 Chrome 专属 API（`chrome.*`） | ✅ | ❌ |
| 需要 Firefox 指纹分布 | ❌ | ✅ |
| 团队只熟悉 Playwright | ✅ | 需要适应 |

**判断方法：** 用 `tools/detector_check.py` 分别跑 patchright 和 camoufox，看哪个的检测项更少。不要凭感觉。

### 1.2 安装

```bash
pip install camoufox[geoip]
python -m camoufox fetch
```

`camoufox fetch` 会下载独立浏览器（约 200MB），不是系统 Chrome。

### 1.3 最小接入

```python
from camoufox.sync_api import Camoufox

with Camoufox(
    headless=False,
    humanize=True,          # 人类化鼠标/键盘
    locale=["zh-CN"],
    os=["windows"],
) as browser:
    page = browser.new_page()
    page.goto("https://example.com", wait_until="domcontentloaded")
    print(page.title())
```

**注意：**

- `Camoufox` 返回的是 Playwright 兼容对象，`page.goto` / `page.evaluate` / `page.locator` 都能用；
- 但 `browser.new_context()` 的参数和 Chromium 不完全一致；
- 持久化 profile 用 `persistent_context=True` + `user_data_dir`（以官方文档为准）。

### 1.4 和 patchright 的切换策略

不要在两个引擎之间随机切换。按「平台」固定：

```python
ENGINE_BY_PLATFORM = {
    "demo_a": "patchright",   # 默认
    "demo_b": "camoufox",     # 实测 camoufox 更稳
}
```

切换前必须做 A/B：

```text
1. 同一账号、同一页面、同一时间段
2. patchright 跑 3 次，记录：验证码次数、条数、耗时
3. camoufox 跑 3 次，记录同样指标
4. 选验证码更少、条数更稳的那个
```

### 1.5 注意事项

- **许可证 MPL-2.0**：修改 camoufox 源码的文件需要开源；只调用不修改没问题。
- **体积**：独立浏览器约 200MB，打包进客户端会显著变大。
- **TLS 指纹**：Firefox 的 TLS 和 Chrome 不同。只适配 Chrome 的站点可能异常。
- **不要和 patchright 共用 profile 目录**：cookie 格式/加密方式不同。

## P2 · rebrowser 检测清单

### 2.1 它检测什么

rebrowser-patches 的价值不在「补丁」，在**检测项清单**。以下是自动化最容易泄漏的点：

| 检测项 | 表现 | 工作包对应 |
|---|---|---|
| `navigator.webdriver` | `true` | `stealth.py` 已处理 |
| `Runtime.enable` 泄漏 | `console.debug` 被调用 | patchright 已处理 |
| `window.chrome` 缺失 | `undefined` | `stealth.py` 已补 |
| `Notification.permission` | `denied` 与自动化不符 | `stealth.py` 已处理 |
| `iframe.contentWindow` | 属性描述符异常 | `stealth.py` 已修 |
| `Permissions.query` | 返回不一致 | `stealth.py` 已处理 |
| `Function.prototype.toString` | 注入函数不是 `native code` | patchright 已处理 |
| UA 与 `sec-ch-ua` 不一致 | 版本对不上 | 不覆写 UA 即可 |
| 时区与 IP 不一致 | `Asia/Shanghai` + 美国 IP | 需要代理侧配置 |
| WebRTC 泄漏 | 暴露真实内网 IP | 需要 `--disable-webrtc` 或代理 |
| 字体列表异常 | 服务器字体缺失 | 用系统 Chrome 即可 |
| `hardwareConcurrency` 异常 | 1 或 64 | 不伪造即可 |
| CDP `Target.setAutoAttach` | 可被检测 | patchright 已处理 |

### 2.2 怎么自检

```bash
python tools/detector_check.py
```

它会打开：

- `bot.sannysoft.com`：基础指纹
- `abrahamjuliot.github.io/creepjs`：深度指纹
- `rebrowser.net/check`：CDP 泄漏

**验收标准：**

```text
[ ] webdriver = false
[ ] window.chrome 存在
[ ] Notification.permission 与真实浏览器一致
[ ] 没有 "Runtime.enable" 相关告警
[ ] 时区 = 代理出口时区
[ ] WebRTC 不暴露真实 IP
```

### 2.3 不建议直接打 rebrowser 补丁

如果你已经用 patchright，大部分修复已内置。再打 rebrowser 补丁可能：

- 与 patchright 的修改冲突；
- 增加维护面；
- 出问题更难定位。

**只把它的清单当自检表。**

## P2 · js-reverse-mcp：动态调试

### 3.1 什么时候用

| 场景 | 用 `js_bundle` | 用 js-reverse-mcp |
|---|---|---|
| HTML 空壳，接口在 JS 里 | ✅ | 可选 |
| JS 压缩但没混淆 | ✅ | 不需要 |
| JS 混淆严重（obfuscator.io） | 可能找不到 | ✅ |
| 需要看运行时参数 | ❌ | ✅ |
| 需要断点/调用栈 | ❌ | ✅ |
| 需要看 WebSocket | ❌ | ✅ |

**顺序：先 `js_api_hunt.py`（10 分钟），找不到再上 js-reverse-mcp（30 分钟+）。**

### 3.2 安装（MCP 配置）

在 Claude Code / Cursor / Codex 的 MCP 配置里加：

```json
{
  "mcpServers": {
    "js-reverse": {
      "command": "npx",
      "args": ["-y", "js-reverse-mcp"]
    }
  }
}
```

> 包名和参数以仓库 README 为准。它支持 Patchright 反检测，适合「有头 Chrome + 断点」。

### 3.3 配合流程

```text
1. js_api_hunt.py 找到候选接口（静态）
2. 接口需要签名/参数不明 → 开 js-reverse-mcp
3. 在 Network 面板找目标请求
4. 下断点，看调用栈
5. 找到参数生成函数
6. 决定：
   ├─ 能在 Node 里跑 → 用 NodeSigner / 独立脚本
   └─ 不能 → 浏览器拦截（examples/04）
```

**不要做的事：**

- 不要为了一个接口把整个混淆包反编译；
- 不要硬编码签名算法（下周就变）；
- 优先「让浏览器自己算」（拦截请求）。

## P3 · pydoll：无 WebDriver 路线

### 4.1 评估

| 维度 | pydoll | patchright |
|---|---|---|
| 许可证 | MIT | Apache-2.0 |
| API | 自有 | Playwright 兼容 |
| 生态 | 小 | 大 |
| 反检测 | CDP 直连，无 WebDriver | 修 CDP 泄漏 |
| 学习成本 | 中 | 低（会 Playwright 就行） |
| 适合 | patchright 失效时的备选 | 默认 |

**结论：暂不集成。** 等遇到「patchright 被针对性检测」的具体案例再评估。

### 4.2 最小示例（备查）

```python
import asyncio
from pydoll.browser import Chrome
from pydoll.browser.options import ChromiumOptions

async def main():
    options = ChromiumOptions()
    options.headless = False
    async with Chrome(options=options) as browser:
        page = await browser.start()
        await page.go_to("https://example.com")
        print(await page.title)

asyncio.run(main())
```

> API 以官方文档为准。它的等待/选择器语义和 Playwright 不同，迁移要重写交互层。

## P3 · Scrapy / Crawlee：调度层

### 5.1 什么时候需要

| 规模 | 方案 |
|---|---|
| < 1000 条/天 | 本包脚本足够 |
| 1000~10000 条/天 | 本包 + 简单队列 |
| > 10000 条/天 | Scrapy / Crawlee |
| 多机分布式 | Scrapy-Redis |

### 5.2 组合架构（Python 路线）

```text
Scrapy（调度 / 去重 / 限速 / 重试）
  │
  ├─ HTTP 接口 URL → Downloader Middleware → curl_cffi 直连
  │
  └─ 需要浏览器的 URL → 转交浏览器服务
        └─ 本包 BrowserSession（单机）或远程浏览器（Steel / Browserbase）
```

**关键：Scrapy 负责「抓哪些 URL」，本包负责「怎么把一个页面渲染出来」。**

不要用 Scrapy 的 Playwright 插件直接跑强风控站点——它的浏览器管理不如本包细。

### 5.3 组合架构（Node 路线）

```text
Crawlee（Node）
  └─ PlaywrightCrawler
        └─ 需要反检测 → 换成 camoufox / patchright-node
```

**代价：** 两套技术栈，维护成本翻倍。除非团队本来就是 Node，否则优先 Python。

### 5.4 不要过早引入

框架的成本：

- 多一层抽象，出问题难定位；
- 依赖升级牵一发动全身；
- 小规模时，框架比业务代码还多。

**判断标准：** 当你开始手写「去重、重试、限速、断点、分布式」中的三个以上，才考虑框架。

## 接入决策表

```text
遇到问题
│
├─ Chromium 被针对？
│   └─ 先 detector_check 对比 → 再考虑 camoufox
│
├─ 怀疑 CDP 泄漏？
│   └─ 对照 rebrowser 清单自检，不要盲目打补丁
│
├─ JS 混淆找不到接口？
│   └─ js_bundle → js-reverse-mcp → 浏览器拦截
│
├─ patchright 完全失效？
│   └─ 评估 pydoll（MIT，无 WebDriver）
│
└─ 规模上来了？
    └─ Scrapy（Python）做调度，本包做渲染
```

## 依赖管理

所有可选依赖都用「装了就启用，没装给提示」：

```python
try:
    from camoufox.sync_api import Camoufox
except ImportError:
    raise RuntimeError(
        "camoufox 未安装。运行：pip install camoufox[geoip] && python -m camoufox fetch"
    )
```

不要写进 `requirements.txt` 的必装项。默认栈越轻，启动越快。
