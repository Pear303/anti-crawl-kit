# 32 · 三分钟上手

这篇只做一件事：让你从 `git clone` 走到「看到自己的报告」，并且每一步都能验证。
不讲原理，原理在 `docs/01` 和 `docs/04`；这里只保证链路通。

## 1. 装

```bash
git clone https://github.com/Pear303/anti-crawl-kit.git
cd anti-crawl-kit
pip install -e ".[all,dev]"
```

只想跑逻辑和测试，`pip install -e ".[dev]"` 就够，不拉 patchright。
国内网络慢可以走 `https://gh-proxy.com/` 前缀。

## 2. 自检

```bash
ack doctor
```

输出分三档：

| 级别 | 含义 | 要不要处理 |
| --- | --- | --- |
| `OK` | 正常 | 不用 |
| `WARN` | 可选能力缺失 | 不影响纯逻辑，用到再装 |
| `FAIL` | 阻塞问题 | 必须处理，退出码 1 |

典型的 WARN：

```text
[WARN]  patchright 未安装
        browser_* 步骤不可用
        → pip install "anti-crawl-kit[browser]"
```

`FAIL` 只有几种：Python 低于 3.10、核心包导入失败、`runs` 目录不可写、临时目录不可写。
这几项都有直接给命令的修复建议，照着粘就行。

给 CI 用加 `--json`，结构是 `{python, checks[], failures, warnings, ok}`。

## 3. 跑第一个配方

两个入口，效果一样，选顺手的：

```bash
ack-ui        # 浏览器控制台，默认 http://127.0.0.1:8766
```

左侧选「内置演示（不联网）」→ 点运行。三秒后能看到日志、步骤状态和报告，
`runs/local_demo/latest.html` 同时落盘。

```bash
ack init recipe              # 生成 my_recipe.yaml
ack-recipe my_recipe.yaml    # 命令行跑，落盘到 runs/my_recipe/
```

`ack init recipe` 生成的模板一定能跑：它只用 `set_var` / `log` / `assert`，
不需要浏览器、网络或额外依赖。先确认这条链路，再往里加你自己的步骤。

## 4. 完全离线的 fixture

```bash
python examples/16_local_fixture.py
```

它读 `examples/fixtures/` 下三份静态 HTML，依次演示：

1. 页面形态判断：`list.html` 是 `ssr`，`spa_shell.html` 是空壳，`captcha.html` 是验证墙
2. DOM 提取：10 张卡片按 `article.card` + 字段选择器抽成记录
3. 分页：从 `a.next` 拿 `?page=2`，不硬拼页码
4. 静默空结果：旧选择器命中 0 条时要先怀疑失效，而不是当成「今天没数据」
5. 空壳页：可见字符 16，数据不在 HTML 里，别写 DOM 选择器
6. 验证墙：识别出来就停

全程不联网、不启动浏览器。改选择器时把它当回归测试：

```python
assert count_matches(html, "article.card") == 10
```

真实站点测试和这种离线断言分开，网络抖动就不会被误判成代码问题。

## 5. 换成自己的页面

```bash
ack init recipe --type http --out jobs/daily.yaml
ack init recipe --type browser --out jobs/page.yaml
```

`--type http` 的模板带 `allow_hosts`，不在列表里的域名会直接报错——这是硬边界，
避免配方被改成任意目标。`--type browser` 的模板用 `browser_goto` + `browser_count`，
第一次建议加 `--headed` 看清页面。

改选择器之前先跑探测，不要凭感觉：

```bash
ack-dom --url "https://quotes.toscrape.com/"
ack-probe --url "https://example.com" --field fansNum --quick
```

## 6. 让它每天跑

```bash
ack-recipe jobs/daily.yaml --baseline auto
```

退出码：

| 码 | 含义 |
| --- | --- |
| 0 | 成功，没有退化 |
| 1 | 配方失败 / 停在 agent 检查点 / 比上一次退化 |
| 2 | 参数错误、配方加载失败、必填输入缺失、落盘失败 |

`--baseline auto` 会在同目录找上一次同类型报告（跳过 `latest.*`，只找更旧的）。
第一次跑没有基线时只 WARN，退出码仍是 0，不会误报。

GitHub Actions 模板在 `examples/ci/daily-recipe.yml`，说明在 `docs/31`。
关键点：全新 runner 上没有历史，必须用 `actions/cache` 恢复 `runs/`，
否则 `auto` 永远找不到基线。

## 7. 常见问题

**`ack` 不是内部或外部命令**
装包时没写进 Scripts 目录。直接 `python -m anti_crawl_kit.tools.ack_cli doctor`，
或者检查 venv 是否激活。

**PyYAML 没装，配方读不了**
`pip install "anti-crawl-kit[config]"`。纯逻辑库不依赖 YAML，但 recipe 和 `ack-ui` 需要。

**Chrome 版本和 patchright 差很多**
`ack doctor` 会 WARN。先照常跑，浏览器步骤异常时再升 patchright，
或者用 `--channel msedge` 换 Edge。

**Windows 控制台中文乱码**
只是显示问题。设置 `$env:PYTHONIOENCODING="utf-8"`，或用 Windows Terminal。

**报告里的时间和我这里不一样**
报告用本地时间；CI 上是 UTC。对比只看顺序，不看绝对时间。
