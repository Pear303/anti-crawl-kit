# 25 · 真实站点冒烟（`ack-smoke`）

> 对应 `v0.4.0`。这一层是**发行门槛**：mock 通过不算验证，必须打真实站点。

---

## 1. 为什么不用 mock

patchright 大切换那次只跑了 mock + 检测站 + 百度，各平台真实 DOM/接口链路
没实测，复盘时被列为**最大风险项**。

mock 能验证「代码不报错」，验证不了：

- 平台是否改版（选择器 0 命中）；
- HTTP 是不是空壳（SPA / JS 渲染）；
- 慢加载会不会被误判成失败；
- 无限滚动有没有停止条件；
- 0 条结果会不会被当成成功。

`ack-smoke` 用**公开练习站**（专门给爬虫练手的沙箱，允许抓）覆盖这些情况。

---

## 2. 9 条默认用例 / 8 种类型

| 用例 | 类型 | 站点 | 断言 |
|---|---|---|---|
| `books_static` | `http_static` | books.toscrape.com | 首页 20 本 |
| `books_pagination` | `http_pagination` | books.toscrape.com | 第 1、2 页各 20 本 |
| `web_scraping_products` | `http_pagination` | web-scraping.dev/products | 第 1、2 页各 5 件 |
| `countries_big_list` | `big_list` | scrapethissite.com/pages/simple/ | `actual == expected == 250` |
| `quotes_js_render` | `js_render` | quotes.toscrape.com/js/ | HTTP 0 条 + 浏览器 10 条 |
| `quotes_slow_load` | `slow_load` | quotes.toscrape.com/js-delayed?delay=10000 | 等满 10s 后仍拿到 10 条 |
| `quotes_infinite_scroll` | `infinite_scroll` | quotes.toscrape.com/scroll | 滚动后 ≥ 10 条，轮数有上限 |
| `saucedemo_login` | `login` | saucedemo.com | `standard_user` 登录后 6 件商品 |
| `quotes_negative_control` | `negative_control` | quotes.toscrape.com | 错误选择器必须判 FAIL |

### 2.1 负向控制是核心

```
正确选择器 div.quote      → 10 条 → PASS
错误选择器 div.quote-xxx  → 0 条  → 必须 FAIL
```

如果错误选择器也能「PASS」，说明检测层把 0 条当成功了——这正是简书/掘金/
百家号 `item_cnt=0` 事故的同类问题。负向控制失败时，`ack-smoke` 直接报
`负向控制失效：检测层把 0 条当成功了`。

### 2.2 类型语义

| 类型 | 判定 |
|---|---|
| `http_static` | HTTP 200 且条目数在 `[expected_min, expected_max]` |
| `http_pagination` | 首页达标，且第二页也 ≥ `expected_page2_min` |
| `js_render` | HTTP 原始 HTML ≤ `http_expected_max`（通常 0），且浏览器达标 |
| `big_list` | 精确等于 `expected_min`（默认也是 `expected_max`） |
| `slow_load` | 轮询等到 `expected_min` 条；可选 `min_elapsed_ms` 证明真的慢 |
| `infinite_scroll` | 滚动后 ≥ `expected_min`；`expected_max=None` 表示只要求下限 |
| `login` | 填表 + 提交 + 登录后 URL 含 `inventory` + 条目达标 |
| `negative_control` | 错误选择器必须让底层判定失败 |

## 3. 用法

```bash
ack-smoke                                   # 全部 9 条（含浏览器）
ack-smoke --no-browser                      # 只跑 5 条纯 HTTP，浏览器用例 SKIP
ack-smoke --only books_pagination,quotes_js_render
ack-smoke --headed                          # 有头，排查登录/滚动
ack-smoke --json smoke.json
ack-smoke --strict                          # SKIP 也视为失败（CI 发行门槛）
ack-smoke --repeat 3                        # 每类跑 3 次，全部通过才算过
```

退出码：

| 码 | 含义 |
|---|---|
| 0 | 无 FAIL |
| 1 | 存在 FAIL（`--strict` 下 SKIP 也算） |
| 2 | 环境/配置错误（缺 `curl_cffi`、`--only` 无匹配） |

依赖：`pip install "anti-crawl-kit[all]"`（HTTP 用 `curl_cffi`，浏览器用 `patchright`）。

## 5. 已知不可用 / 注意事项

- **`the-internet.herokuapp.com` 本机不可达**（40s 超时），不要加进默认矩阵。
- `automationexercise.com`、`practicesoftwaretesting.com` 可用，但前者偶发广告弹窗，
  后者是 Angular SPA，默认矩阵不纳入，避免 flaky。
- 练习站也会改版。用例失败时先看 `actual` 和 `metrics`：
  - `page2.count` 掉了 → 分页结构变了；
  - `js_render` 的 `http_count > 0` → 站点改成 SSR，用例需更新；
  - `slow_load` 的 `min_elapsed_ms` 不满足 → 站点去掉了延迟，用例需更新。
- 真实平台接入后，把平台用例放在**独立配置**里，不要改默认练习站矩阵；
  默认矩阵的作用是「验证工具本身没坏」。

## 6. 新增用例

```python
from anti_crawl_kit import SmokeCase, SmokeKind

CASE = SmokeCase(
    name="my_platform_list",
    kind=SmokeKind.HTTP_PAGINATION,
    url="https://example.com/list",
    item_selector="div.card",
    expected_min=20,
    expected_max=20,
    page2_url="https://example.com/list?page=2",
    expected_page2_min=20,
)
```

然后：

```python
from anti_crawl_kit import run_smoke
report = run_smoke([CASE], http_client=my_client, page=my_page)
assert not report.has_fail(), report.render()
```
