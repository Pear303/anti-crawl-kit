# 29 · 可视化报告与本地控制台

> 对应 `v0.10.1`。目标不是做拖拽采集器，而是把「判断结果」变成人能快速看懂的东西：
> 单文件 HTML 报告（`ack-report`）+ 只监听本机的控制台（`ack-ui`）。

---

## 1. 为什么不做拖拽编辑器

市面上已经有很多可视化采集产品：

| 类型 | 代表 | 强项 |
|---|---|---|
| 无代码采集平台 | 八爪鱼、Maxun、Apify | 点选字段、定时任务、云端运行 |
| 可视化工作流 | n8n、Automa、影刀 RPA | 节点编排、系统集成 |
| AI 浏览器 agent | browser-use、Skyvern、Stagehand | 自然语言驱动浏览器 |
| 可视化调试器 | Playwright UI / codegen | 录制、回放、选择器调试 |

本项目的优势不在「点」，在「判断」：

- 页面是 SSR 还是空壳，数据在 DOM、全局状态还是 XHR；
- 403/429 是该降级、换路径，还是该停；
- 请求成功但 0 条，是没数据还是参数写错了；
- 遇到验证墙，继续重试还是截图停下。

这些判断做成拖拽画布会丢掉，而且正面撞 Maxun / Apify。所以只做两层：

1. **报告**：把已有的 JSON 结论渲染成人能看的页面；
2. **控制台**：把「选配方 → 填参数 → 跑 → 看日志」这条最短路径搬到浏览器里。

---

## 2. 第一层：单文件 HTML 报告

### 2.1 支持的输入

`ack-report` 自动识别六种结构：

| 类型 | 来源 | 页面重点 |
|---|---|---|
| `audit` | `ack-audit` 的 `run_report.json` | 路径矩阵、选型建议、被排除路径、验收缺口 |
| `health` | `ack-health --json` | 按维度分组的 OK/WARN/FAIL/SKIP |
| `smoke` | `ack-smoke --json` | 每个用例的状态、结果、耗时、错误 |
| `assess` | `ack-assess` 的 `assessment.json` | G0~G4 关卡、决策、评分、缺口 |
| `run` | `RunReport.to_dict()` | 静默失效四字段（expected/actual/coverage/degraded） |
| `recipe` | `RecipeRun.to_dict()` | 步骤、耗时、agent 检查点 |

### 2.2 用法

```bash
# 单个文件，输出到同目录同名 .html
ack-report --input runs/health.json

# 指定输出
ack-report --input runs/audit.json --out reports/audit.html

# 批量转换 + 生成 index.html（递归扫描子目录，跳过 profiles/.venv 等目录）
ack-report --dir runs

# 输出到独立目录，保留 runs/ 下的子目录结构
ack-report --dir runs --out reports

# 只指定索引位置，报告仍写在输入目录
ack-report --dir runs --out reports/index.html
```

各 CLI 也能直接出 HTML：

```bash
ack-health --config ack_health.yaml --json runs/health.json --html runs/health.html
ack-smoke --json runs/smoke.json --html runs/smoke.html
ack-audit --config examples/platforms/bilibili_audit.yaml --out runs/bilibili
ack-assess --config examples/assessments/books.yaml
```

`ack-audit` 和 `ack-assess` 默认就会在输出目录里写 `audit.html` /
`assessment.html`。

### 2.3 页面约束

- **单文件**：CSS 和 JS 全部内嵌，不引用 CDN，断网也能开；
- **安全**：所有动态文本经过 `html.escape`，平台返回的 `<script>` 不会被执行；
- **深色模式**：跟随系统 `prefers-color-scheme`；
- **可筛选**：路径矩阵和表格可以按「通过 / 警告 / 失败 / 未测」过滤；
- **可打印**：打印时去掉阴影和筛选按钮；
- **缺字段不崩**：任何字段缺失都降级成 `-`，不会因为一条脏数据打不开。

报告里不放 cookie、token 和原始响应体；需要原始数据时展开「原始 JSON」，
内容仍然经过转义。

## 3. 第二层：本地 Web 控制台

### 3.1 只做四件事

```text
列配方 → 填参数 → 运行 → 看日志 / 报告
```

没有拖拽、没有选择器点选、没有账号池、没有云端执行。

### 3.2 启动

```bash
ack-ui
# http://127.0.0.1:8766

ack-ui --headed                  # 浏览器有头，方便看登录/滚动
ack-ui --channel msedge          # 用 Edge
ack-ui --recipes examples/recipes --runs runs
ack-ui --open                    # 启动后自动打开浏览器
```

默认只监听 `127.0.0.1`。如果改成 `--host 0.0.0.0`，启动时会打印警告：
局域网内其他人也能访问，而控制台能执行本机配方。

### 3.3 运行流程

1. 左侧列出 `--recipes` 目录下的 YAML/JSON 配方；
2. 选中后按 `inputs` 定义生成表单，默认值直接带出来；
3. 点「运行」后，后端起一个线程执行 `run_recipe`。`POST /api/run` 的
   `recipe` 字段既接受相对路径（`product_list.yaml`），也接受
   `/api/recipes` 返回的配方 `id`（`product_list`）；
4. 页面通过 SSE（`/api/jobs/<id>/events`）接收步骤事件：
   `step_start` / `step_ok` / `step_failed` / `step_skipped` / `needs_agent` / `done`；
5. 结束后可以打开 `/api/jobs/<id>/report` 看这次运行的 HTML 报告。

配方里只要有 `browser_*` 步骤，控制台会自动启动浏览器；也可以手动勾选
「启动浏览器」。纯 HTTP 配方不会开浏览器。

### 3.4 agent 检查点

`run_recipe` 遇到 `kind: agent` 会返回 `needs_agent` 和结构化 `handoff`。
控制台会显示检查点的 prompt 和上下文，给一个输入框：

- 输入 JSON 就按对象传给 agent；
- 不是 JSON 就按字符串传；
- 点「继续」后调用 `resume_recipe`，从 `next_index` 接着跑。

这让「确定性步骤 + 人工判断」可以在页面上完成，不需要回终端改脚本。

### 3.5 安全边界

| 风险 | 处理 |
|---|---|
| 任意路径读取 | 配方必须落在 `--recipes` 目录内，`..` 越界返回 403 |
| 报告目录穿越 | `/runs/...` 只允许 `--runs` 目录内的文件 |
| 日志泄露 cookie | 事件经过 `redact_mapping`，cookie/token 字段替换成 `<redacted>` |
| 远程访问 | 默认只监听 `127.0.0.1`；改地址会显式警告 |
| 作业泄漏 | 内存队列最多保留 30 个作业，完成旧作业自动清理 |

控制台没有鉴权，这是有意的：它是本机工具，不是多用户服务。要远程用，
请自己加反向代理和认证，不要直接把端口暴露到公网。

## 4. 模块关系

```text
recipe.py ──run_recipe(on_event=...)──┐
                                      ├──> ui.py ──> ui_assets.py（单页）
report.py ──render_html()─────────────┘
   ▲
   ├── tools/report_cli.py（ack-report）
   ├── tools/path_audit.py（audit.html）
   ├── tools/health_cli.py（--html）
   ├── tools/smoke_cli.py（--html）
   └── tools/assess_cli.py（assessment.html）
```

`report.py` 只依赖标准库；`ui.py` 用 `http.server`，不引入 FastAPI/Flask。
这样 `pip install -e ".[dev]"` 就能跑控制台，不需要额外装 Web 框架。

## 5. 测试

```bash
pytest tests/test_report.py tests/test_ui.py -q
```

覆盖：

- 六种报告的类型识别和渲染；
- XSS 转义（`<script>` 不能出现在页面里）；
- 空数据不崩；
- 单文件 / 目录批量转换；
- 控制台的配方列表、运行、事件流、agent resume；
- 路径越界拦截；
- HTTP API 端到端（GET/POST/报告下载）。

浏览器相关的用例仍然由 `ack-smoke` 覆盖，控制台测试不启动真实浏览器。
