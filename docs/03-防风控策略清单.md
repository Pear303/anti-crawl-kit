# 03 · 防风控策略清单

> 这份清单按「账号 → 环境 → 行为 → 协议 → 熔断」排列。
> 被风控时从上往下排查，不要一上来就换指纹。

---

## 1. 账号层

- [ ] 每个平台独立 profile 目录，不混用。
- [ ] 一个 profile 只登一个账号；多账号不要在同一浏览器实例里切换。
- [ ] 登录频率控制：同一平台短时间反复登录/扫码，最容易触发「系统繁忙」。
      实测：连续登录 3 次以上，平台侧会临时限制登录接口。
- [ ] 登录失败后冷却 30 分钟 ~ 数小时，不要立刻重试。
- [ ] 优先复用已有登录态：先检测，已登录就跳过扫码（避免无谓触发登录风控）。
- [ ] 账号操作（发布、改资料）与采集分开时段，不要同时高频。

---

## 2. 环境层

- [ ] 用真实系统 Chrome / Edge，不用 Playwright 内置 Chromium。
- [ ] 不覆写 UA（跟随真实浏览器）。
- [ ] `locale=zh-CN`、`timezone=Asia/Shanghai` 与账号归属一致。
- [ ] 代理：同一账号固定出口 IP；优先住宅/移动，机房 IP 容易被标记。
- [ ] 不要在同一个 IP 上同时跑几十个账号。
- [ ] 时区/语言/IP 三者不要互相矛盾（例如美国 IP + 中文时区 + 中文账号）。
- [ ] 屏幕分辨率、DPR 跟随真实机器，不强制伪造。

---

## 3. 行为层

- [ ] 导航前随机延时（同域 1-4s，首次 0.2-0.8s）——`guard.py` 已默认开启。
- [ ] 滚动用人类节奏：加速→巡航→减速 + 30% 概率回滚。
- [ ] 点击前贝塞尔鼠标轨迹，点击点随机落在元素 30%-70% 区域。
- [ ] 键入逐字符 50-150ms，5% 思考停顿，3% 错字自纠（仅 ASCII）。
- [ ] 翻页间隔随页数递增（`AdaptiveRateLimiter`：每 10 页 +0.5s）。
- [ ] 单次任务不要连续跑几小时；分批 + 中途休息。
- [ ] 不要并发打开几十个页面；同一浏览器 2-3 个 tab 足够。

**注意：** 行为模拟不能通过 `isTrusted` 级检测。它的价值是降低「固定节奏」
这一明显特征。真正的反检测主力是环境层 + 协议层。

---

## 4. 协议层

- [ ] 先访问页面拿 cookie，再调接口；不要冷启动直接打 API。
- [ ] 带 `Referer` / `Origin`，且与目标站一致。
- [ ] 视频/音频直链必须带 Referer（CDN 防盗链），否则 403/空文件。
- [ ] 签名参数（`a_bogus`、`w_rid`、`X-s`）从页面运行时取，不硬编码。
- [ ] `msToken`、`verifyFp`、`buvid3` 等设备标识跟随会话，不跨账号复用。
- [ ] HTTP 直连用 `curl_cffi` 的 `impersonate`，不要用裸 `requests`。
- [ ] 请求头顺序、大小写尽量与真实浏览器一致（curl_cffi 已处理大部分）。

---

## 4.5 内容层：投毒（poisoning）

> 这是最容易被忽略的一层：站点不拦你请求，而是**污染你拿到的数据**。

### 原理

站点故意往内容源（第三方 API / 静态书库）里混入「毒章」：

- 看着像正文，实际是广告、乱码、错乱文字、重复段落；
- 官方前端识别后整章丢弃（`polluted=true` → `return null`），真人读者看不到；
- 裸调 API 的爬虫如果不过滤，就会把垃圾一起导出。

有的站还带「众包回传」钩子：把你读到的毒章回报给站点，帮它完善识别。

### 常见信号

| 信号 | 说明 |
|---|---|
| API 返回 `polluted` / `is_poisoned` / `bad` 字段 | 最直接，优先判断 |
| 正文重复段落比例高 | 毒章常见手法 |
| 正文长度异常短 / 异常长 | 对比同章节其他源 |
| 广告关键词密度高 | 「请记住本站」「最新章节」「手机阅读」 |
| 乱码 / 替换字符 | `\ufffd`、大量非目标语言字符 |
| 低熵 | 字符种类少，像填充 |

### 应对

```text
1. API 返回 polluted=true → 整章丢弃，不重试（重试还是毒章）
2. 没有 polluted 字段 → 本地质量校验（content_quality.py）
3. 多源交叉：同一章节对比两个源，差异大就标记
4. 抽样人工复核：每天抽 1~2 章
5. 不要触发回传钩子：跑页面时拦截 chapterHook / report 类请求
```

**代码：** [`src/anti_crawl_kit/content_quality.py`](../src/anti_crawl_kit/content_quality.py)
—— `check_content(text, polluted=...)` 一行完成六项校验；示例见
[`examples/13_content_quality.py`](../examples/13_content_quality.py)。

### 为什么不能「重试」

毒章不是网络错误，重试只会重复拿到毒章，还会触发站点的回传/风控。

**它和验证墙一样，是「止损信号」，不是「重试信号」。**

## 5. 熔断与降级

统一用 `classify_http_result` 判断：

| 信号 | 分类 | 动作 |
|---|---|---|
| 429 | `RATE_LIMITED` | 指数退避 30-60s；连续 3 次停止任务 |
| 401/403 | `BLOCKED` | 降级浏览器；仍失败则换账号/换 IP |
| 验证码页面 | `CAPTCHA` | 暂停，提示人工；不要自动破解 |
| 「请登录」 | `LOGIN_REQUIRED` | 等待登录 / 复用 profile |
| 签名错误 | `SIGNATURE_FAILED` | 重新从页面取签名，不要重试旧参数 |
| 5xx | `NETWORK_ERROR` | 重试 3 次后放弃 |

**退避公式：**

```
delay = min(15, 3 * 2^attempt) * random(0.8, 1.2)
```

连续失败 5 次应停止任务并告警，而不是无限重试。

---

## 6. 验证码处理原则

1. **不自动破解。** 滑块/点选/极验的自动破解成本高、稳定性差，
   而且会显著提高账号风控等级。
2. **检测到就暂停**，打印明确提示，让用户手动完成。
3. **独立预算**：验证码 100s、登录 200s，互不挤占。
4. **通过后复检**：重导航到目标页后，再检测一次验证码（可能二次触发）。
5. **失败要诚实**：区分「浏览器被关」「验证码未完成」「未登录」「真无结果」，
   不要统一报「被风控」。

---

## 7. 绝对不要做的事

- ❌ 用同一个 profile 同时跑多个账号
- ❌ 短时间反复登录/扫码
- ❌ 固定 1 秒间隔疯狂翻页
- ❌ 无 Referer 直接下载视频直链
- ❌ 伪造 UA 版本与真实 Chrome 不一致
- ❌ 用 `playwright-stealth` 硬编码 navigator/WebGL
- ❌ 验证码自动破解
- ❌ 失败后无限重试
- ❌ 把 Cookie / token 上传服务端或写进日志
- ❌ 在生产环境用无头模式跑登录

---

## 8. 风控自检表（每周/每次平台改版后）

```bash
# 1. 反检测基线
python tools/detector_check.py

# 2. 真实导航 + evaluate
python examples/01_hello_browser.py --url "https://目标站"

# 3. 登录态是否还有效（不触发登录）
python examples/03_login_and_captcha.py --platform 目标平台

# 4. 接口是否仍可用
python examples/05_http_only.py

# 5. 采集是否静默失效（条数、字段完整率）
python examples/07_config_driven.py examples/platforms/目标.yaml --out output/check.json
```

判断标准：

- `webdriver=false`
- 连续 3 次采集不触发验证码
- 字段完整率 > 90%
- 条数与页面显示数量一致
- 关窗后 10s 内退出
