# 07 · 平台速查表

> 接一个新平台前，先在这里查三件事：**数据在哪、要不要登录、会怎么死**。
> 表里的接口路径、参数名、选择器都来自 2026-07 ~ 2026-09 的实测，
> **平台改版后一律以 `tools/dom_probe.py` 的现场结果为准**。

---

## 0. 怎么用这张表

1. 先看「机制总表」定位平台类型，决定走 L1~L4 哪一层（分层定义见 `01-决策与方法论`）。
2. 再看对应平台的「坑」——90% 的时间浪费在重复踩这些坑。
3. 最后按「节奏建议」设置并发和间隔，不要一上来就拉满。

**层级缩写**

| 缩写 | 含义 | 工具 |
|---|---|---|
| L1 | 纯 HTTP 直连接口 | `HttpClient` / `curl_cffi` |
| L2 | 浏览器打开一次，读 SSR 全局状态 | `page.evaluate(..., isolated_context=False)` |
| L3 | 浏览器拦截页面自己发的 XHR | `PageAdapter.capture_responses` |
| L4 | 解析 DOM | `GenericCollector` / 自定义脚本 |

**一条通用原则：能 L1 就 L1，L1 被签名挡住就 L3。不要自己实现平台签名。**

| 简书 | 列表 HTML 片段 | `slug`（`/p/{id}`） | 公开 | ★★☆☆☆ | L4 |
| 掘金 | 公开 API `query_list` | `article_id` | 公开 | ★★★☆☆ | L1 / L2 |
| 百家号 | SSR + XHR | `id` | 阅读公开，发布要登录 | ★★★★☆ | L4 |

> 单篇阅读大多很松，一上量就完全不是一回事。

## 2. 分平台详解

### 2.1 抖音（douyin.com）

**入口**

- 搜索：`https://www.douyin.com/search/{关键词}?type=video`
- 用户主页：`https://www.douyin.com/user/{sec_uid}`
- 视频详情：`https://www.douyin.com/video/{aweme_id}`

**数据在哪**

- 页面 XHR：`/aweme/v1/web/general/search/single/`、`/aweme/v1/web/aweme/post/`、`/aweme/v1/web/comment/list/`
- SSR：脚本里的 `RENDER_DATA`（URI 编码 JSON）或 `window._ROUTER_DATA`，**随版本变化**，以探测结果为准。
- 列表项字段：`aweme_id`、`desc`、`author.sec_uid`、`statistics.digg_count`、`video.play_addr`。

**登录 / 验证码**

- 未登录搜索会弹登录框；高频直接出滑块（`captcha` iframe）。
- 登录态看 `sessionid` / `sid_guard` cookie，或页面右上角头像。

**坑**

1. 搜索翻页有深度上限，翻到后面返回空。**用「最新/最热」排序 + 时间切片**（按天/周）代替无限翻页。
2. 请求带 `a_bogus`（新）/ `X-Bogus`（旧）签名，自己算必然过期。**拦截页面请求，不要构造。**
3. 视频直链 `play_addr` 有时效和地域限制，下载要带 `Referer: https://www.douyin.com/`。
4. 评论区默认只加载一小段，要滚动/点击「展开更多」。
5. 同一账号短时间搜多个关键词，第二个词开始就容易出验证码。

**节奏建议**：单账号单轮 ≤ 30 条；关键词之间 30~60s；日采集控制在 300 条以内。

### 2.2 快手（kuaishou.com）

**入口**

- 搜索：`https://www.kuaishou.com/search/video?searchKey={关键词}`
- 主页：`https://www.kuaishou.com/profile/{user_id}`
- 详情：`https://www.kuaishou.com/short-video/{photoId}`

**数据在哪**

- GraphQL：`POST https://www.kuaishou.com/graphql`
  - 搜索：`operationName=visionSearchPhoto`
  - 主页作品：`operationName=visionProfilePhotoList`
  - 详情：`operationName=visionVideoDetail`
- 请求体关键字段：`pcursor`（翻页游标）、`searchSessionId`。
- 必须带 `Cookie: did=web_xxx`；登录态还要 `kuaishou.web.cp.api_st`、`passToken`、`bUserId`。

**登录 / 验证码**

- 搜索需要登录；未登录会跳登录页或返回空列表。
- 验证码以滑块为主，偶发「操作频繁」。

**坑**

1. **登录 cookie 校验别用 `kuaishou.server.web.st`**——那是旧值。生产上踩过：扫描登录成功但程序判定未登录，根因就是校验了过时 cookie。
2. GraphQL 响应是 `data.visionSearchPhoto.feeds`，不是数组平铺，解析要按 `operationName` 分支。
3. `pcursor` 为 `"no_more"` 表示结束，不是空字符串。
4. 视频详情接口会返回 `visionVideoDetail.status === 2` 表示作品被删/私密。

**节奏建议**：搜索词之间 20~40s；GraphQL 单页 20 条；不要并发多个搜索。

### 2.3 B站（bilibili.com）

**入口**

- 热门：`https://www.bilibili.com/v/popular/all`
- 搜索：`https://search.bilibili.com/all?keyword={关键词}`
- UP 主空间：`https://space.bilibili.com/{mid}/video`
- 视频详情：`https://www.bilibili.com/video/{bvid}`

**数据在哪**

- 热门：`https://api.bilibili.com/x/web-interface/popular?ps=20&pn=1`（公开，最省事）
- 排行榜：`https://api.bilibili.com/x/web-interface/ranking/v2?rid=0&type=all`
- 搜索：`/x/web-interface/wbi/search/type?keyword=...&search_type=video`，需要 `w_rid` + `wts`（WBI 签名）
- 空间：`/x/space/wbi/arc/search?mid=...&pn=1&ps=30`，需要 WBI + 登录态
- 详情：`/x/web-interface/view?bvid=...`（公开）
- 播放地址：`/x/player/playurl?bvid=...&cid=...&qn=80`（部分清晰度要登录）

**登录 / 验证码**

- 热门/排行榜/视频详情基本公开。
- 搜索、空间、关注列表、收藏夹需要登录（`SESSDATA`）。
- 高频会 412（`请求被拦截`），不是验证码，是风控。

**坑**

1. **WBI 的 `img_key`/`sub_key` 每天轮换**，`w_rid` 由二者 + 参数 + `wts` 计算。不要硬编码，也不要自己实现——拦截页面请求最稳。
2. 先访问一次 `https://www.bilibili.com/` 拿 `buvid3` cookie，否则部分接口返回 `-352`。
3. 412 后**至少冷却 10 分钟**，继续重试只会延长封禁。
4. 空间视频列表第一页经常混入置顶视频，去重按 `bvid`。
5. 分 P 视频要读 `pages` 数组，`cid` 每 P 不同。
6. 热门页 JS 里写的是相对路径 `/x/web-interface/popular`，真实域名是 `api.bilibili.com`；
   用 `js_api_hunt.py --api-host api.bilibili.com` 重拼，不要按页面 origin 拼（会 404）。

**节奏建议**：公开接口 1~2s/次；搜索 3~5s/次；单 IP 并发 ≤ 2。

### 2.4 小红书（xiaohongshu.com）

**入口**

- 搜索：`https://www.xiaohongshu.com/search_result?keyword={关键词}&source=web_search_result_notes`
- 主页：`https://www.xiaohongshu.com/user/profile/{user_id}`
- 笔记详情：`https://www.xiaohongshu.com/explore/{note_id}?xsec_token={token}&xsec_source=pc_search`

**数据在哪**

- SSR：`window.__INITIAL_STATE__`
  - 搜索：`state.search.feeds` / `state.search.noteList`
  - 主页：`state.user.notes`
  - 详情：`state.note.noteDetailMap[note_id].note`
- XHR：`/api/sns/web/v1/search/notes`、`/api/sns/web/v1/user_posted`、`/api/sns/web/v1/feed`
- 列表项关键字段：`note_id`、`xsec_token`、`display_title`、`user.user_id`、`interact_info.liked_count`。

**登录 / 验证码**

- 2024 年起搜索必须登录；未登录只能看首页推荐流。
- 登录态看 `web_session` cookie 或 `state.user.loggedIn`。
- 验证码：滑块、点选、`300012` 风控码；频繁操作会直接封 24h。

**坑**

1. **`__INITIAL_STATE__` 里有 `undefined` 字面量**，Python `json.loads` 会炸。正确做法是在浏览器里 `JSON.stringify` 后再取，或直接 `page.evaluate("() => window.__INITIAL_STATE__.search")` 让 Playwright 序列化。
2. **详情页必须带 `xsec_token`**，不带会 404 或空白。token 只能从列表项/搜索响应里拿，且有时效。
3. 笔记详情接口是 `/api/sns/web/v1/feed`，POST body 里 `source_note_id` + `xsec_token` 缺一不可。
4. 图片 `sns-webpic-qc.xhscdn.com` 有防盗链，下载带 `Referer: https://www.xiaohongshu.com/`。
5. 主页笔记分「笔记/收藏/赞过」，未登录只能看笔记 tab。
6. 小红书对**账号关联**很敏感：同一台机器多个账号切换，容易一起被限流。profile 必须按账号隔离。

**节奏建议**：单账号单轮 ≤ 20 条；翻页间隔 8~15s；日采集 ≤ 150 条；出现一次滑块就停 30 分钟。

### 2.5 知乎（zhihu.com）

**入口**

- 搜索：`https://www.zhihu.com/search?type=content&q={关键词}`
- 问题：`https://www.zhihu.com/question/{question_id}`
- 回答：`https://www.zhihu.com/question/{qid}/answer/{answer_id}`
- 专栏：`https://zhuanlan.zhihu.com/p/{article_id}`
- 用户：`https://www.zhihu.com/people/{url_token}`

**数据在哪**

- SSR：`window.__INITIAL_STATE__`（问题页 `entities.answers`、专栏页 `entities.articles`）
- API：`/api/v4/search_v3`、`/api/v4/members/{token}/answers`、`/api/v4/questions/{id}/answers`
- 签名：`x-zse-96`（由 `d_c0` cookie + URL + 参数计算），另有 `x-requested-with`。

**登录 / 验证码**

- 搜索、用户主页、关注列表需要登录；未登录会跳 `signin` 或返回 403。
- 登录态看 `z_c0` cookie。
- 验证码：滑块/点选，风控页文案「系统检测到您的网络环境存在异常」。

**坑**

1. `x-zse-96` 算法随前端版本变，**不要自己实现**；用 L3 拦截。
2. 未登录访问问题页也会限制回答数量（只给前几条），别以为是解析漏了。
3. 回答正文懒加载：滚动到回答卡片才渲染，直接取 `innerHTML` 可能只有「展开阅读全文」。
4. 图片 `pic*.zhimg.com` 有防盗链；公式是 `img` 不是文本，需要保留 `data-formula`。
5. 盐选/付费内容不要碰。

**节奏建议**：搜索 5~10s/次；单账号日 ≤ 200 条；连续 3 次 403 就换号或停 1 小时。

### 2.6 微博（weibo.com / m.weibo.cn）

**入口**

- PC 搜索：`https://s.weibo.com/weibo?q={关键词}`
- 用户主页：`https://weibo.com/u/{uid}`
- 移动端主页：`https://m.weibo.cn/u/{uid}`
- 微博详情：`https://m.weibo.cn/detail/{mid}`

**数据在哪**

- 移动端 API（推荐）：`https://m.weibo.cn/api/container/getIndex`
  - 用户微博：`containerid=107603{uid}`
  - 搜索：`containerid=100103type=1&q={关键词}`
  - 翻页：`page=2`（部分接口用 `since_id`）
- 返回 `data.cards[].mblog`，字段 `id`、`mid`、`text`、`attitudes_count`、`comments_count`、`reposts_count`。
- 长文：`https://m.weibo.cn/statuses/extend?id={mid}`。

**登录 / 验证码**

- 用户主页公开可看少量；搜索必须登录（`SUB` cookie）。
- 访客态会生成 `SUB`/`SUBP`，但很快失效。
- 风控：403/418、跳「安全验证」、账号异常。

**坑**

1. `m.weibo.cn` 的 `containerid` 拼错一个字符就返回空 cards，不报错。
2. 微博正文是 HTML，需要保留 `<a>` 话题/@，但要去掉 `全文` 链接。
3. 转发微博的正文在 `retweeted_status`，别只取 `text`。
4. 图片 `wx*.sinaimg.cn` 有防盗链，带 `Referer: https://weibo.com/`。
5. PC 端 `s.weibo.com` 对自动化最敏感，优先移动端。

**节奏建议**：移动端 API 2~4s/次；搜索 10s/次；单账号日 ≤ 300 条。

### 2.7 今日头条（toutiao.com）

**入口**

- 搜索：`https://so.toutiao.com/search?keyword={关键词}`
- 用户主页：`https://www.toutiao.com/c/user/{user_id}/`
- 文章：`https://www.toutiao.com/article/{item_id}/`
- 视频：`https://www.toutiao.com/video/{item_id}/`

**数据在哪**

- 列表：XHR `/api/pc/list/user/feed`、`/api/pc/list/feed`，参数含 `category`、`max_behot_time`、`_signature`。
- 文章页 SSR：`window.__INITIAL_STATE__` 或 `articleInfo`。
- 正文容器：`.article-content` / `article`；视频在 `video` 标签的 `src`。

**登录 / 验证码**

- 大部分内容公开；搜索高频会要求登录/验证。
- 登录态看 `sessionid` / `sid_tt` cookie。

**坑**

1. `_signature` 是 JS 生成的，随版本变；不要硬算，拦截页面请求。
2. 列表分页用 `max_behot_time`（上一页最后一条的时间戳），不是 `page`。
3. 文章正文里混有「展开」按钮和推荐卡片，取 `.article-content` 后要清掉 `.pgc-card`。
4. 视频直链有时效，且分清晰度，需要 `Referer`。
5. 头条系（抖音/西瓜）共用部分风控，同一 IP 高频会一起受影响。

**节奏建议**：3~6s/次；搜索 10s/次；单账号日 ≤ 300 条。

### 2.8 CSDN（blog.csdn.net）

**入口**

- 用户博客：`https://blog.csdn.net/{username}?type=blog`
- 文章列表 API：`https://blog.csdn.net/community/home-api/v1/get-business-list?page=1&size=20&businessType=blog&username={username}`
- 文章详情：`https://blog.csdn.net/{username}/article/details/{articleId}`
- 搜索：`https://so.csdn.net/so/search?q={关键词}`

**数据在哪**

- 列表：**优先用上面的公开 API**，返回 `data.list[]`，字段 `articleId`、`title`、`url`、`postTime`、`viewCount`、`diggCount`、`commentCount`。
- 详情：正文 `#content_views`；标题 `#articleContentId` / `.title-article`；阅读数 `.views-count`（**动态加载，约 3~5s**）。
- 搜索：`.search-list .search-item`（2026-09 实测该选择器返回 0，改用 `a[href*="/article/details/"]` 兜底）。

**登录 / 验证码**

- 基本公开；高频触发 `acw_sc__v2` JS challenge（521）或滑块。
- 登录态看 `UserToken` cookie。

**坑**

1. **个人主页 DOM 在 2026-08-11 改版**：`.profile-intro-name .name`、`.user-profile-head-name .name`、`.user-head-pic-name`、`.data-info .item` 全部失效。新结构：昵称 `.user-profile-head-name > div:first-child`、头像 `.user-profile-avatar img`、简介 `.introduction-fold`、统计 `.user-profile-statistics-num` + `-name`。
2. **阅读数 `.views-count` 是异步加载的**，立刻取会得到空或 0，必须显式等待（3~5s）。
3. 列表页只显示相对时间（「2天前」），准确日期要去详情页 `<time>` 取。
4. 正文有反爬水印 token（形如 `mmMwWLliI0fiflO`），用 `clean_anti_crawl_watermark` 清洗。
5. 代码块 `<pre><code>` 要保留语言 class，否则还原不了高亮。
6. 首次访问可能返回 521 + `acw_sc__v2`，用浏览器过一次即可，不要用 HTTP 硬撞。

**节奏建议**：API 1~2s/次；详情 2~4s/次；单 IP 并发 ≤ 3。

### 2.9 微信公众号（mp.weixin.qq.com）

**入口**

- 文章：`https://mp.weixin.qq.com/s/{shortid}`
- 完整参数：`https://mp.weixin.qq.com/s?__biz={biz}&mid={mid}&idx={idx}&sn={sn}`
- 历史列表：`https://mp.weixin.qq.com/mp/profile_ext?action=home&__biz={biz}&scene=124#wechat_redirect`

**数据在哪**

- 文章页 SSR：正文 `#js_content`；标题 `#activity-name`；作者 `#js_name`；发布时间 `#publish_time`。
- 图片是懒加载：`data-src` 才是真地址，`src` 是占位图。
- 阅读量/点赞：`#js_read_area`、`.like_num`，部分账号不显示。

**登录 / 验证码**

- 单篇文章正文公开。
- 历史列表需要微信生态登录态：`__biz` + `key` + `uin` + `pass_ticket`，`key` 约 20 分钟过期。
- 频繁访问会出「环境异常，完成验证后即可继续访问」。

**坑**

1. **`key` 有时效**，批量采集必须在过期前跑完，过期重新扫码。
2. 正文默认 `visibility: hidden`（防抓），需要 `document.getElementById('js_content').style.visibility = 'visible'`。
3. 图片必须把 `data-src` 写回 `src` 再下载，否则拿到占位图。
4. 文章可能被删（`该内容已被发布者删除`）或违规（`此内容因违规无法查看`），要区分「删除」和「解析失败」。
5. 历史列表返回的是 HTML 片段（`general_msg_list` 是转义 JSON），要二次 `json.loads`。
6. 公众号文章没有稳定的公开搜索接口；「搜一搜」结果依赖登录态和客户端 UA。

**节奏建议**：单篇 3~5s；批量 ≤ 50 篇/轮；两轮之间 ≥ 10 分钟；出现「环境异常」立即停。

---

### 2.10 简书（jianshu.com）

**入口**

- 用户主页：`https://www.jianshu.com/u/{user_id}`
- 文章：`https://www.jianshu.com/p/{slug}`
- 搜索：`https://www.jianshu.com/search?q={关键词}`

**数据在哪**

- 用户文章列表：`https://www.jianshu.com/u/{user_id}?order_by=shared_at&page=2` 返回 **HTML 片段**，不是 JSON。
- 文章页：正文 `.article` / `article`；标题 `.title`；作者 `.author .name`。
- 列表项：`ul.note-list li`，链接 `a.title`，元信息 `.meta`。

**登录 / 验证码**

- 阅读公开；点赞/发布要登录。
- 风控较低，高频偶发 403。

**坑**

1. 列表是 HTML 片段，不能用 `response.json()`；用 `page.content()` 或 `lxml` 解析。
2. 图片 `upload-images.jianshu.io` 有防盗链。
3. 文章可能被锁（`该文章已锁定`），要跳过。
4. **发布端是 CodeMirror5**：直接 `fill()` 不生效，必须 `keyboard.insert_text` + 合成 paste；新建草稿要先保存再插入正文。

**节奏建议**：2~3s/次；可并发 2~3。

### 2.11 掘金（juejin.cn）

**入口**

- 用户文章：`https://juejin.cn/user/{user_id}/posts`
- 文章：`https://juejin.cn/post/{article_id}`
- 搜索：`https://juejin.cn/search?query={关键词}`

**数据在哪**

- 列表 API：`POST https://api.juejin.cn/content_api/v1/article/query_list`
  - body：`{"user_id":"...","cursor":"0","sort_type":2}`
  - 需要 `Cookie: aid=2608; uuid=...`（随便一个 uuid 即可，但要有）
- 文章页 SSR：`window.__NUXT__`（Nuxt），正文 `.article-content` / `#articleContent`。
- 字段：`article_id`、`title`、`ctime`、`view_count`、`digg_count`、`comment_count`。

**登录 / 验证码**

- 阅读公开；发布/点赞要登录。
- 风控中等：无 cookie 或高频会 403。

**坑**

1. `query_list` 的 `cursor` 是字符串 `"0"`，不是数字。
2. 文章页是 Nuxt，`__NUXT__` 是函数调用不是纯 JSON，别直接 `json.loads`。
3. 发布端是 CodeMirror6，`insert_text` 可用，图片上传走 file chooser。
4. 掘金文章里的代码块和外链会被处理，采集时保留原始 `innerHTML` 更稳。

**节奏建议**：API 1~2s/次；详情 2~3s/次。

### 2.12 百家号（baijiahao.baidu.com）

**入口**

- 文章：`https://baijiahao.baidu.com/s?id={id}`
- 作者页：`https://baijiahao.baidu.com/u?app_id={app_id}`

**数据在哪**

- 文章页 SSR：正文 `.article-content` / `#article`；标题 `.article-title`。
- 作者页：XHR 列表接口（schema 随版本变），或 DOM `.video-list` / `.article-list`。
- 视频：`video` 标签 + `src`，部分走 `baijiahao.baidu.com/video` 中转。

**后台数字（零浏览器）**

- 百家号后台 `https://www.baidu.com/my/index` 的动态/关注/粉丝**不在 HTML 里**，是前端 JS 拉的。
- 接口：`GET https://www.baidu.com/my/dynamic_num`（`baseURL="/my"`，`withCredentials:true`）。
- 带登录 cookie 直接请求，返回 `dynamicNum / subscribeNum / fansNum`，以及 `uk` 和各页跳转 URL。
- 方法见 [`09-JS包找接口.md`](09-JS包找接口.md)。

**登录 / 验证码**

- 阅读公开；发布必须登录（百家号后台）。
- 风控高：百度安全验证（滑块/点选），发布端新手引导 `cheetah-tour` 会挡按钮。

**坑**

1. 发布端正文在 **UEditor iframe** 里，普通 `fill` 找不到；要 `frame_locator` 或直接 JS 注入。
2. `cheetah-tour` 新手引导浮层要先关掉，否则按钮点不到。
3. 作者页列表接口 schema 变过（`items` 字段调整），解析要做兼容。
4. 百度系图片有防盗链，带 `Referer: https://baijiahao.baidu.com/`。
5. 正文里混有「展开全文」和推荐卡片，取容器后要清。

**节奏建议**：3~5s/次；发布操作串行，不要并发。

### 2.13 百度搜索（baidu.com）

**入口**

- `https://www.baidu.com/s?wd={关键词}&pn={页码}`

**数据在哪**

- 结果容器 `#content_left`；每条 `.result` / `.c-container`；标题 `h3 a`；摘要 `.c-abstract`。
- 真实 URL 常在 `a` 的 `href` 里是百度跳转链，需要跟随或解析 `mu` 属性。

**登录 / 验证码**

- 公开；高频直接「百度安全验证」滑块。

**坑**

1. 百度结果页对自动化识别很敏感，`curl_cffi` 比 Playwright 更容易过（TLS 指纹）。
2. 跳转链要还原真实 URL，别把 `www.baidu.com/link?url=` 存进库。
3. 广告位（`.ec_result`、`[data-tuiguang]`）要过滤。
4. 翻页 `pn` 步长 10，超过 76 页基本不给。
5. 需要更稳的搜索数据时，优先考虑 Bing / 搜狗微信 / 平台站内搜索，而不是硬刚百度。

**节奏建议**：5~10s/次；单 IP 日 ≤ 500 次；出验证码停 1 小时。

### 2.14 视频号（channels.weixin.qq.com）

**入口**

- 视频号助手：`https://channels.weixin.qq.com/`
- 动态页：`https://channels.weixin.qq.com/web/pages/feed`
- 单条：登录后从列表点进去，URL 不稳定，以 `objectId` 为准。

**数据在哪**

- 必须登录后才有数据；接口带签名（`_log_finder_*` 系列参数）。
- 视频直链在 `finder.video.qq.com`，带 `decode_key` / `encfilekey`，有时效。
- 列表项字段：`objectId`、`desc`、`createtime`、`likeCount`、`commentCount`。

**登录 / 验证码**

- 必须微信扫码登录；登录态有效期短，容易掉。
- 风控极高：异地/多账号/高频都会触发。

**坑**

1. 没有公开 Web 搜索入口，别指望像 B站那样 L1 直连。
2. `decode_key` 有时效，下载要立刻做，且带 `Referer: https://channels.weixin.qq.com/`。
3. 登录态失效不会报错，只会返回空列表——要主动检测 `login` 状态。
4. 不建议批量；如果必须做，单账号 + 低频 + 人工在场。

**节奏建议**：单账号日 ≤ 50 条；操作间隔 15~30s；只做自己有权访问的内容。

## 3. 平台签名参数对照

> **看到这些参数，直接放弃自己构造请求，改 L3 拦截。**

| 平台 | 签名参数 | 依赖 | 建议 |
|---|---|---|---|
| 抖音 | `a_bogus` / `X-Bogus` | UA、时间、body | L3 |
| 快手 | `sig3`（部分接口） | cookie、body | L3 |
| B站 | `w_rid` + `wts`（WBI） | `img_key`/`sub_key` 每日轮换 | L3 或复用公开接口 |
| 小红书 | `x-s` / `x-t` | URL、body、时间 | L3 |
| 知乎 | `x-zse-96` | `d_c0`、URL、参数 | L3 |
| 今日头条 | `_signature` | URL、UA、时间 | L3 |
| 微博 | 无强签名，主要靠 cookie | `SUB` | L1 可行 |
| CSDN | `acw_sc__v2`（JS challenge） | 首次访问 | 浏览器过一次 |
| 掘金 | 无强签名，需 `aid`/`uuid` | cookie | L1 可行 |
| 公众号 | `key` + `pass_ticket` | 登录态、时效 | 登录态 + 低频 |

**为什么不要自己实现：** 签名算法是前端 JS 混淆产物，随版本周更；你花两天逆出来的版本，可能下周就失效。拦截浏览器自己发的请求，等于永远用最新算法。

## 4. 跨平台通用坑

### 4.1 计数归一

`1.2万`、`10万+`、`1,093`、`3.4k`、`2.1w` 都要归一成整数。
用 `anti_crawl_kit.text.parse_count`，不要每个平台写一遍。

### 4.2 时间归一

- 相对时间：`刚刚`、`3分钟前`、`2小时前`、`昨天`、`3天前`、`2026-08-01`。
- 相对时间必须带「抓取时刻」做基准，否则入库后无法复现。
- 列表页时间通常不准，**详情页的 `<time>` / `publish_time` 才是权威**。

### 4.3 图片懒加载

常见属性：`data-src`、`data-original`、`data-lazy-src`、`data-actualsrc`。
公众号、知乎、小红书、B站专栏都有。取图前先 `scrollIntoView` 或直接读 `data-src`。

### 4.4 防盗链

下载图片/视频时带对应 Referer：

| 平台 | Referer |
|---|---|
| 小红书 | `https://www.xiaohongshu.com/` |
| 微博 | `https://weibo.com/` |
| 知乎 | `https://www.zhihu.com/` |
| B站 | `https://www.bilibili.com/` |
| 抖音 | `https://www.douyin.com/` |
| 公众号 | `https://mp.weixin.qq.com/` |
| 百家号 | `https://baijiahao.baidu.com/` |

### 4.5 详情页 token

| 平台 | 必需参数 | 来源 |
|---|---|---|
| 小红书 | `xsec_token` + `xsec_source` | 列表项 |
| B站 | `bvid` 或 `aid` | 列表项 |
| 抖音 | `aweme_id` | 列表项 |
| 快手 | `photoId` | 列表项 |
| 公众号 | `__biz` + `mid` + `idx` + `sn` | 文章 URL |
| 微博 | `mid` / `bid` | 列表项 |

**列表项里的 token 不要丢**，很多平台详情页没它直接 404。

### 4.6 分页模型

| 模型 | 平台 | 注意 |
|---|---|---|
| `page` / `pn` | B站、CSDN、百度、微博 | 页码从 1 开始还是 0 开始，各平台不同 |
| `cursor` / `pcursor` | 快手、掘金、小红书 | 结束标记：`no_more` / `"0"` / `has_more=false` |
| `max_behot_time` | 头条 | 用上一页最后一条时间戳 |
| 滚动加载 | 小红书、抖音、知乎 | 必须等「加载中」消失再取，否则重复/漏项 |

### 4.7 反爬水印

部分平台（公众号、头条、CSDN）会在正文里插入不可见字符或短 token。
统一用 `clean_anti_crawl_watermark` 清洗，别在业务代码里写正则。

### 4.8 登录态判定

不要只看「有没有 cookie」，要看平台自己的判定锚点：

- 抖音：右上角头像 / `sessionid`
- 快手：`kuaishou.web.cp.api_st` + `passToken` + `bUserId`
- B站：`SESSDATA` + 导航栏头像
- 小红书：`web_session` + `state.user.loggedIn`
- 知乎：`z_c0` + 头像
- 微博：`SUB` + 昵称
- 公众号：`key` + `pass_ticket`（时效短）

**推荐做法**：cookie 存在性做快路径，页面锚点做最终确认；两者都过才算登录。

## 5. 风控等级与节奏建议

| 等级 | 平台 | 单轮上限 | 请求间隔 | 日上限（单账号） | 触发后处理 |
|---|---|---|---|---|---|
| ★★★★★ | 抖音、小红书、知乎、公众号、视频号 | 20~30 | 8~20s | 100~300 | 立即停 30~60min，换号需换 profile |
| ★★★★☆ | 快手、微博、百家号、百度 | 30~50 | 5~10s | 300~500 | 停 15~30min，降速 |
| ★★★☆☆ | B站、头条、掘金 | 50~80 | 3~6s | 500~800 | 停 10min，检查 412/403 |
| ★★☆☆☆ | CSDN、简书 | 100+ | 1~3s | 1000+ | 降并发即可 |

> 这些数字是「保护账号」的保守值，不是平台真实阈值。
> 真实阈值随 IP、账号权重、设备指纹、时段变化，**先用一半的量跑一周**。

### 出现这些信号，立刻停

- 滑块/点选验证码出现一次以上
- 连续 2 次 403 / 412 / 418
- 列表返回空但页面手动能打开
- 登录态突然失效
- 响应时间从 200ms 涨到 2s+
- 出现「环境异常」「操作频繁」「安全验证」字样

**停止比换 IP 更有效。** 很多风控是「行为累计分」，越撞越深。

## 6. 采集前 60 秒检查清单

```text
[ ] 目标数据是否公开可见？有没有碰隐私/付费/私信？
[ ] 用 dom_probe 确认：SSR 状态？XHR 接口？DOM 候选？
[ ] 接口有没有签名参数？（有 → L3，不自己构造）
[ ] 详情页需不需要 token？（需要 → 从列表项透传）
[ ] 登录态怎么判定？cookie + 页面锚点都验证了吗？
[ ] profile 是否按平台/账号隔离？
[ ] 图片/视频是否带 Referer？
[ ] 分页结束条件是什么？会不会死循环？
[ ] 验证码/登录是否独立计时？关窗能否 10s 内退出？
[ ] 限频参数是否比上表更保守？
```
