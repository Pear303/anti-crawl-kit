# 11 · 工程红线与验收清单

> 这些不是「最佳实践」，是**踩过事故之后不能再犯的错**。
> 每条都标了「为什么」和「怎么检查」，agent 可以直接拿去当 gate。

---

## 一、浏览器与环境（8 条）

### 1. patchright 必须与系统 Chrome 大版本同步

**为什么：** 版本 gap 会导致 CDP 首导航完成事件丢失，页面空白转圈，`goto` 却返回成功。Chrome 自动更新不可控，升级 patchright 是唯一对齐手段。

**已落地（代码检查，不是文档口号）：**

`BrowserSession.__enter__` 启动时调用 `_check_versions()`，日志形如：

```text
[env] patchright=1.62.2 chrome=156.0.8078.74
```

- `detect_chrome_version()`：Windows 读 `Application/<version>/` 子目录，macOS/Linux 跑 `--version`
- `detect_patchright_chromium()`：读 patchright 自带 `browsers.json`
- 差 0：OK；差 1：WARN；**差 ≥2：RuntimeError（fail-fast）**
- 显式跳过：`BrowserSession(skip_version_check=True)`，只用于已实测可用的环境

对齐规则：patchright 1.62.x ↔ Chromium 151/152。差一个大版本就升级。

---

### 2. 不要裸 `chromium.launch()`，用 `channel`

**为什么：** 裸 launch 会找 Playwright 内置 Chromium，通常没装；而且内置 Chromium 的指纹和真实 Chrome 不一致。

**正确：**

```python
context = chromium.launch_persistent_context(
    profile_dir,
    channel="chrome",          # 系统 Chrome
    headless=False,
)
```

**降级链：** `chrome` → `msedge` → 显式 `executable_path`。都没有就报错，不要静默切内置。

---

### 3. 不要覆写 UA

**为什么：** 固定 UA 与真实 Chrome 版本、`sec-ch-ua`、`navigator.userAgentData` 矛盾，是最明显的检测信号。

**正确：** 用系统 Chrome 默认 UA，不传 `user_agent` 参数。

---

### 4. 登录/验证码阶段不要拦截图片

**为什么：** 二维码、滑块图、点选图被 `abort` 后，用户永远等不到验证通过。

**正确：**

```python
BrowserSession(block_resources=False)   # 登录阶段
BrowserSession(block_resources=True)    # 批量采集阶段（可选）
```

---

### 5. 不要只信 `page.is_closed()`

**为什么：** 浏览器进程被杀后 CDP 断连，Playwright 收不到 `targetDestroyed`，`is_closed()` 会**假阴性返回 False**，等待循环继续空转。

**正确：** 两段式。

```python
def is_page_closed(page):
    if page.is_closed():          # 快路径：True 即死
        return True
    try:
        page.evaluate("() => 1")  # 探针：1~5ms
        return False
    except Exception as exc:
        return _looks_closed(exc) # 只认 closed/target
```

---

### 6. 不要把 `destroyed` 当成关窗

**为什么：** 页面导航期间 `evaluate` 会稳定抛 `Execution context was destroyed`，窗口其实还活着。把它当关窗，会把「登录成功跳转」误判成「用户关窗」。

**正确：** `_CLOSED_MARKERS = ("closed", "target")`，不收 `destroyed`。

---

### 7. 杀浏览器进程要认主进程

**为什么：** 按「命令行含 profile 目录」选目标，会先撞见 `crashpad-handler` 等 `--type=` 子进程；杀了它们，浏览器主体没事，CDP 还通。

**正确：** 主进程特征 = 命令行含 `user-data-dir` 且**不含** `--type=`。

---

### 8. profile 按「平台 + 账号 + 场景」隔离

**为什么：** 一个目录混用多平台/多账号，cookie 互相覆盖，账号被关联。

**规则：**

```text
profiles/{platform}/{account_alias}/
profiles/{platform}/{account_alias}_creator/   # 创作者中心单独
```

**禁止：** 用 `storage_state` 跨 profile 导入导出，平台风控会拒绝。

---

## 二、行为与风控（4 条）

### 9. 验证墙是止损信号，不是重试信号

**为什么：** 重试只会刷新出一个新验证码，同时加深风控评分（很多平台是行为累计分），最后从「待验证」变「封禁」。

**正确：**

```python
if gate.check(page).detected:
    gate.stop(page, info)   # 截图 + 通知 + 抛异常
```

**唯一例外：** 首次登录阶段可以等人（双时钟），批量阶段不能等。

---

### 10. 不要自动破解验证码

**为什么：** 破解成功也会留下行为特征；失败则直接触发更严的风控。

**正确：** 检测 → 通知 → 等人 → 继续。人不在就停。

---

### 11. 固定节奏比随机更容易被识别

**为什么：** 每 2.000 秒请求一次、每次滚动 800px、瞬间填完表单，都是机器特征。

**正确：**

- 同域导航间隔 1~4s 随机；
- 滚动距离和停顿随机；
- 逐字键入，30~100ms 随机延迟，偶尔停顿；
- 不要追求「完全拟人」——目标是降低机械节奏，不是骗过行为级检测。

---

### 12. 批量阶段不要等人

**为什么：** 你不知道用户什么时候回来；空等烧预算，重试加深风控。

**正确：** 批量阶段命中验证墙 → 立即停 + 通知 + 退出码 2。让调度器告警，不要自动重跑。

---

## 三、数据与解析（4 条）

### 13. 不要用 `0` 表示缺失

**为什么：** 无法区分「播放量真的是 0」和「没采到」。下游统计会全错。

**正确：** 缺失用 `None`；只有真实 0 才用 `0`。

```python
views = parse_count(raw.get("view"))   # 解析失败返回 None
```

---

### 14. 同一份数据至少留两条路

**为什么：** 接口会加签、会限流、会改字段；只留一条路，改版即死。

**正确：** 策略链 + `source_strategy` 标记（见 `10-采集器工程架构.md` 第 2 节）。

---

### 15. 选择器必须有兜底

**为什么：** 平台改版通常只改一层 class，没有兜底就要当天修。

**正确：**

```yaml
card_selector: "section.note-item"
fallback_selectors:
  - "div.note-item"
  - "[data-testid='note-item']"
```

**验收：** 把主选择器故意改错，采集器应该靠兜底还能跑，并打 WARN 日志。

---

### 16. 接口常量带 `last_verified`

**为什么：** 半年后没人知道这个接口还灵不灵。

**正确：**

```python
# last_verified: 2026-11-04
POPULAR_URL = "https://api.example.com/x/web-interface/popular"
```

巡检时按日期排序，优先验证最老的。

## 四、工程与交付（8 条）

### 17. 长循环必须可取消

**为什么：** 用户点了「取消」，程序还在滚动第 8 页，体验极差。

**正确：** 每轮循环检查取消信号。

```python
for round_no in range(max_rounds):
    raise_if_cancelled(on_cancel_check)
    ensure_alive(page)
    ...
```

---

### 18. 不要吞验证墙和关窗异常

**反例：**

```python
try:
    ...
except Exception:
    return []      # 验证墙被吞，任务显示「成功但 0 条」
```

**正确：**

```python
except (ChallengeDetected, BrowserClosedError):
    raise
except Exception as exc:
    log.warning(...)
    return []
```

---

### 19. 改代码必须跑冒烟，不能只看 import

**为什么：** 源码 `import` 通过，打包产物可能缺模块；协议冒烟通过，真实 GUI 链路可能还是坏的。

**正确：**

- 采集器：跑一次真实平台，确认条数 > 0；
- 打包产物：用产物跑完整协议，不只测源码；
- 关键链路：真实登录一次，看 DB/日志终态。

**冒烟必须与真实链路同源。** 只验证「require 成功」不够。

---

### 20. 多 agent 并发禁止 `git reset` / `git checkout --`

**为什么：** 会一次性丢弃工作区全部未提交改动；多 agent 共用一个工作区时，另一个 agent 的改动也会没。

**正确：**

- 改完即提交；
- 需要回退时，`git stash` 或 `git diff` 后手工还原；
- 打包流程不得包含破坏性 git 命令。

---

### 21. 不要用 PowerShell `Set-Content` 改源码

**为什么：** PowerShell 5.1 的 `-Encoding UTF8` 会写 BOM，破坏中文注释和 JSON 解析。

**正确：** 用编辑工具改；必须用脚本时，用 `[System.Text.UTF8Encoding]::new($false)`。

---

### 22. 版本号多处同步

**为什么：** 漏一处会导致「升级循环」或「版本显示错误」。

**Python 包（本工作包）：** 版本号只写一处 —— `src/anti_crawl_kit/__init__.py` 的 `__version__`。
`pyproject.toml` 用 `dynamic = ["version"]` + `attr` 读取，**不要**再写一遍。
`requirements.txt` 由 `scripts/gen_requirements.py` 生成，标「自动生成勿改」。

**桌面客户端 / Tauri：** 改版本后 `git diff` 逐处核对，至少包括：

```text
package.json / package-lock.json
tauri.conf.json
Cargo.toml / Cargo.lock
handlers.js（多处）
测试断言
```

---

### 23. 重打安装包必须 bump 版本

**为什么：** 同版本号 `isNewer('x','x') = false`，已装用户永远收不到修复。

**正确：** 每次重打 `0.3.x → 0.3.x+1`，即使只改了一行。

---

### 24. 打包后验证产物，不是源码

**为什么：** pkg / PyInstaller 可能出现「同一模块多份副本、内容不同」，源码测试全过，产物链路还是坏的。

**正确：**

```text
[ ] 产物文件时间戳是本次构建
[ ] 产物里搜关键字符串（修复标记）
[ ] 用产物跑一次完整协议
[ ] 真实链路走一次（登录/采集/发布）
```

### 25. 临时探测脚本和 cookie 文件必须清理

**为什么：** probe 脚本散落会让下次找不到哪份是最终版；cookie 明文落盘是泄露风险。

**正确：**

```text
[ ] probe 脚本统一放 output/probe/，任务结束删除
[ ] cookie 优先用 --cookie 参数或环境变量，不写文件
[ ] 必须写文件时，用 output/probe/.cookie，任务结束删除
[ ] 脚本固化后，删除对应的临时 probe
```

**反例：** 某次 4 任务的会话写了 20+ 个 `probe_*.py`，散落在系统临时目录；真实 cookie 也写成了 `*_cookie.txt`，任务结束未清理。

## 五、新采集器验收清单

上线前逐项打勾，任何一项不过都不算完成。

### 功能

```text
[ ] 采集条数 = 页面显示条数（±10%）
[ ] 必填字段完整率 ≥ 95%
[ ] 同一页跑两次，重复率 = 0
[ ] 缺失字段用 None，不是 0
[ ] 每条数据有 source_strategy
```

### 稳定性

```text
[ ] 连续跑 3 次不触发验证码
[ ] 滚动/翻页能正常停止（连续 N 轮无新增）
[ ] 主选择器改错后，兜底还能跑
[ ] 接口 403 时能降级，不直接失败
[ ] 中断后能从断点续跑，不重复
```

### 可观测

```text
[ ] 每阶段有日志（prepare/auth/fetch/parse/persist）
[ ] 字段缺失有追踪记录
[ ] 验证墙有截图 + HTML + meta
[ ] 日志能定位到「哪一步、哪个选择器、多少条」
```

### 可中断

```text
[ ] 关窗后 10s 内退出
[ ] 取消信号在滚动/翻页循环内生效
[ ] 退出码语义正确（0/2/3/4/130）
```

## 六、上线前 30 分钟检查

```text
[ ] 目标平台手动打开一次，确认账号正常、不弹验证
[ ] 跑一次单页采集，确认条数和字段
[ ] 跑一次阈值测试（把 max_items 设为 1）
[ ] 跑一次关窗测试（手动关浏览器，看是否 10s 内退出）
[ ] 跑一次验证墙测试（访问必出验证的页面，看是否硬停 + 通知）
[ ] 查看磁盘剩余空间（截图/HTML 快照会占空间）
[ ] 确认日志目录可写
```

## 七、平台改版应急流程

```text
1. 确认是改版还是风控
   ├─ 手动打开页面正常 → 改版/接口变
   └─ 手动也弹验证 → 风控，先冷却

2. 改版：定位哪一层变了
   ├─ tools/dom_probe.py        → DOM 结构
   ├─ tools/js_api_hunt.py      → 接口地址
   └─ page.capture_responses()  → 实际请求

3. 只改最小范围
   ├─ 选择器 → 配置文件
   ├─ 接口 → constants.py
   └─ 字段 → parse 函数

4. 回归
   ├─ 单页 20 条
   ├─ 连续 3 次
   └─ 兜底选择器也测一遍

5. 记录
   └─ 在平台速查表补一条「改版记录」
```

**不要做的事：**

- 不要因为一次失败就重写整个采集器；
- 不要同时改选择器和接口（出问题无法归因）；
- 不要把兜底策略删掉「因为主策略已经修好了」。

## 八、事故复盘模板

```markdown
## 现象
（用户看到什么，什么时候开始）

## 影响
（多少任务失败、多少数据缺失、是否影响账号）

## 根因
（一句话；如果是多层，写清主因和诱因）

## 修复
（改了什么文件、什么逻辑）

## 验证
（怎么证明修好了；源码/产物/真实链路分别验证了什么）

## 可迁移的教训
（下次怎么避免；要不要加检查项/告警）

## 待办
（还有哪些没做，什么时候做）
```

**复盘的价值在最后两节。** 只写「修好了」等于没复盘。
