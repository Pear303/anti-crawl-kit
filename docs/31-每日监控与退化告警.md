# 每日监控与退化告警

`ack-report --baseline` 解决「这次比上次差在哪」，但手工指定基线文件不适合
天天跑。这一篇讲怎么把它变成定时任务：跑配方 → 落盘 → 自动找上一次 → 有退化
才告警。

## 1. 三个零件

| 零件 | 作用 | 产物 |
|---|---|---|
| `ack-recipe` | 命令行跑配方 | `runs/<recipe>/<时间戳>.json\|html` + `latest.*` |
| `runs.find_previous_report` | 在同目录找上一次同类型报告 | 基线路径 |
| `ack-report --baseline auto` | 渲染 HTML 并输出退化摘要 | 退出码 0/1/2 |

`ack-ui` 和 `ack-recipe` 共用 `anti_crawl_kit/runs.py`，所以两边落盘的目录结构
一致，控制台跑出来的历史也能直接拿去做基线。

## 2. `ack-recipe`

```bash
# 跑一次，落盘到 runs/local_demo/
ack-recipe examples/recipes/local_demo.yaml

# 传输入；值先按 JSON 解析，失败按字符串
ack-recipe recipes/daily.yaml --inputs url=https://example.com --inputs limit=50

# 和上一次对比
ack-recipe recipes/daily.yaml --baseline auto

# 指定基线文件
ack-recipe recipes/daily.yaml --baseline runs/daily/20261113-090000.json
```

退出码：

| 码 | 含义 |
|---|---|
| 0 | 配方 `done`，且没有退化（找不到历史也算 0，只告警） |
| 1 | 配方失败 / 停在 agent 检查点 / 基线对比发现退化 |
| 2 | 参数错误 / 配方加载失败 / 缺少必填输入 / 落盘失败 |

配方里声明的 `inputs.<name>.default` 会自动补上；`required: true` 且没有
default 的输入必须用 `--inputs name=...` 传，否则直接退出码 2，不会带着空值
跑到一半才 KeyError。

`needs_agent` 是中间态，不落盘。定时任务里应该把它当失败处理，人工用
`ack-ui` 或 `resume_recipe` 继续。

## 3. `--baseline auto` 怎么选基线

规则在 `runs.find_previous_report`：

1. 只看**同目录**的 `*.json`；
2. 跳过 `latest.json`（它是副本，拿来比等于和自己比）、`index.json`、`report.json`；
3. 只选**比当前文件更旧**的（mtime 更早；同一秒用文件名时间戳排序），避免
   `--dir` 批量处理时旧报告反过来和新报告比；
4. 在候选里按从新到旧找第一份**类型相同**的（`recipe` / `health` / `smoke` …）。

找不到时打印 `[WARN] 没有找到上一次的 ... 报告，本次不对比`，退出码仍是 0。
第一次跑、或者刚清空 `runs/` 时属于正常情况。

`ack-report --dir runs --baseline auto` 会对每份报告各自对比上一次，最后汇总
`合计退化 N`。目录模式只支持 `auto`，指定具体基线文件会退出码 2。

## 4. 本地定时

Linux / macOS（crontab，每天 09:00）：

```cron
0 9 * * * cd /srv/anti-crawl && \
  .venv/bin/ack-recipe recipes/daily.yaml --runs runs --baseline auto \
  >> logs/daily.log 2>&1
```

Windows（任务计划程序）：

```powershell
$action = New-ScheduledTaskAction -Execute "C:\path\to\ack-recipe.exe" `
  -Argument "recipes\daily.yaml --runs runs --baseline auto" `
  -WorkingDirectory "C:\path\to\project"
$trigger = New-ScheduledTaskTrigger -Daily -At 9:00
Register-ScheduledTask -TaskName "anti-crawl-daily" -Action $action -Trigger $trigger
```

判断结果看退出码，不要 grep 日志文本。退化时退出码 1，接 `Notifier` 或系统
告警都行。

## 5. GitHub Actions

模板见 [`examples/ci/daily-recipe.yml`](../examples/ci/daily-recipe.yml)，复制到
`.github/workflows/` 后改 `RECIPE` 和 `cron` 即可。

关键点：**GitHub 每次都是全新 runner**，不恢复历史的话 `--baseline auto`
永远找不到基线，等于没对比。模板用 `actions/cache/restore` + `actions/cache/save`
把 `runs/` 传下去，`restore-keys` 前缀匹配最近一次缓存。

`actions/cache` 有空闲 7 天自动清理的策略，每天跑不会触发。如果改成每周跑，
要注意这个上限。

告警只在退出码非 0 时开 Issue，并且会先搜同名未关闭 Issue：有就追加评论，没有
才新建，避免一次故障刷出几十个 Issue。

需要浏览器的配方不要在同一个 workflow 里跑：patchright + Chrome 下载会显著
拉长时长，建议单独一个 `daily-recipe-browser.yml`，并接受它更慢。

## 6. 告警策略

只报「退化」，不报「每次运行」。具体是：

- 用例/指标变差（`OK -> FAIL`、`WARN -> FAIL`、耗时明显上升）
- 用例消失（`removed`）
- 配方失败 / 停在检查点

以下不算退化，不要告警：

- 新增用例（`added`）
- 改善（`FAIL -> OK`）
- 首次运行没有基线
- 类型不一致（这是配置错误，应该退出码 2 直接修）

## 7. 常见坑

- **`runs/` 被加进 `.gitignore`**：正常。历史报告走 artifact / cache，不要提交。
- **报告里有敏感字段**：`persist_run` 会写 `ui.inputs` / `cli.inputs`，但输入是
  脱敏后的（`redact_mapping`）。不要把 Cookie 直接塞进 `--inputs`，用
  `cookies_env` 从环境变量读。
- **HTML 报告很大**：每份都内嵌样式，历史多了会占空间。定期清理只留 JSON，
  或只缓存 `*.json`。
- **mtime 被复制操作改掉**：`find_previous_report` 在 mtime 相同时用文件名排序，
  `YYYYmmdd-HHMMSS` 格式天然有序，所以 cache 恢复后仍然正确。
- **`--dir` 会转换全部历史**：历史特别多时改用 `--input latest.json
  --baseline auto`，只处理当天。
